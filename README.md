## Текущая разработка BlackRazid

Ветка перешла на **1.13.0-dev.4**. Это **не готовое единое расширение** по запросу «всё, кроме прочих обработчиков».
В коде есть отдельные жажда/фляга, фонарь/зарядка, две гранаты, **9 собственных типов патронов и 20 магазинов/баллонов**.
Подключены **базовые механики всех 22 собственных стволов BlackRazid**: магазины/россыпь, дробь,
сохранение патронника, давление/ручной взвод, огнемёт. Это отдельные ID `blackrazid_*`, не MCMOD-подмена.
**Модули, родные 3D-модели оружия/боеприпасов/рук и анимации ещё не готовы**: пока исходные плоские иконки.
Добавлен первый собственный блок мутантов: **крыса, паук, библиотекарь** с родными моделями/анимациями/звуками
и два спавнера с сохраняемыми таймерами. [Поведение и явные адаптации](docs/BLACKRAZID_MUTANTS.md).
Остальные 9 мутантов/9 спавнеров, транспорт/пути и тоннели/окружение остаются в работе.
[Честный статус, управление и адаптации](docs/BLACKRAZID_EXPANSION.md),
[отчёт по каждому стволу/мутанту](docs/blackrazid-expansion-report.json).
Разработческий runtime `d75760f` прошёл [сборку Java 8 / Forge и reobfuscation](https://github.com/nikakirill60-a11y/444/actions/runs/41328758242):
**114 Python-проверок, 211 JUnit-тестов**. Полноценный игровой прогон и визуальная приёмка не выполнены.
Последняя выданная пользователю сборка **1.12.0** остаётся ниже; готовый общий выпуск пока не объявлен.

## Исправления по игровой проверке — 1.11.1

1. **Мачете от третьего лица:** отдельная матрица по рукояти 3D-модели, без унаследованного поворота диагональной плоской иконки. Обе основные руки.
2. **Аптечка от третьего лица:** масштаб 1,25 вместо 0,55 — примерно **в 2,27 раза больше**, с опорой снизу коробки. Первое лицо/лечение не изменены.
3. **Оружие:** предплечья направлены к разным наружным локтям вместо общей плоскости приклада; камера немного отдалена/опущена, модель уменьшена. Одобренные поза/матрицы револьвера Flan **не изменены**. Новые позы ещё требуют визуальной приёмки.
4. **Дюп ПНВ/часов:** настоящая причина воспроизведена новым тестом. Entity.equals/hashCode сравнивает ID; WeakHashMap объединяла клиентского и серверного игроков с одинаковым ID, позволяя клиентскому клику менять серверный слот до серверного исполнения. Теперь слабые ключи по идентичности объектов, атомарное создание, отдельные хранилища для сторон и нового объекта после respawn. Дополнительно надевание ПНВ по ПКМ завершается после ванильного восстановления количества в creative.

Регрессии проверяют реальные Entity.equals/hashCode и MetroContainer, предсказание/серверный клик/ack, смену объекта и повторное открытие. Это сильнее прежних тестов с Mockito-игроком, но не заменяет игру и полноценный сетевой прогон. **Уже созданные дубликаты автоматически не удаляются.** [Сценарии проверки](docs/TESTING.md).

## Единая сборка MCMOD — 1.11.0

Все изменения объединены в одном JAR. Java 8/Forge build и reobfuscation успешно завершены; ссылка выше ведёт на проверенный артефакт 1.12.0 с последующими дополнениями. Архив около 154 МБ. Это сборка для игровой приёмки, не подтверждение полного прогона клиента/сервера.

- **Все 15 зарегистрированных стволов MCMOD**: АК-74, Ашот, Дуплет, Убойник, ВСВ, Револьвер, Ублюдок, Вентиль, Превед, Рельса, Тихарь, АК-2012, АКС-74У, РПК, Хельсинг. Отдельные ID `mcmod_*`, исходные OBJ/атласы/иконки/звуки; оружие Flan не заменяется. Модели упакованы gzip без изменения исходных байтов.
- **M — модификации и ремонт** оружия в основной руке: глушитель, оптика/коллиматор, увеличенный магазин для АК-74/Вентиля/Преведа, лазер. Совместимость, цены, снятие и ремонт проверяет сервер. Расходуются металл/химия; цены указаны в подсказках. При снятии полного увеличенного магазина лишние патроны возвращаются; при нехватке места операция отменяется, а не удаляет их. Повторное снятие не даёт повторный возврат.
- **V — удерживать для накачки/зарядки** Тихаря, Хельсинга, Рельсы. Максимум 30; выстрел расходует единицу. Давление влияет на урон. ПКМ — огонь, Alt — прицел, R — перезарядка; новый магазин в survival пуст.
- Скорость MCMOD-пули **20 блоков/тик**, гравитация **0,001**, исходный гауссовский разброс; дробовики выпускают шесть дробин. Учтены исходные пороги состояния и штраф глушителя. Износ до нуля блокирует стрельбу, но не удаляет оружие.
- Исправлены живые транзакции слота часов: обычные клики, цифровая смена и другие операции больше не заменяют изменяемый ванилью стек устаревшим снимком. Автоматические тесты выполняют реальный `Container.slotClick`; точный игровой сценарий пользователя ещё требует приёмки.
- Хват прежнего револьвера Flan **сохранён**. У остальных изменены углы предплечий; визуальное качество этой правки **не подтверждено запуском Minecraft**.

**Границы переноса:** обычные 20 HP; точные старые формулы брони не добавляются. GUI использует исходные картинки в новой компактной раскладке, а не копирует старый экран пиксель-в-пиксель. `modScope=3`/`modPriklad` — незавершённые заглушки исходника, не выдаются за рабочие установки. Исходная безусловная отмена смерти не переносится: обработчик PlayerDrops там пуст, подпись «невыпадаемый» сама не реализует удержание. Для явно помеченных вещей действует прежний NoDrop порта. Подробный аудит и адаптации: [MCMOD.md](docs/MCMOD.md), [отчёт оружия](docs/mcmod-firearms-report.json). **Игровая приёмка клиента/выделенного сервера остаётся открытой.**

## Анимации, нашивки и редстоун-ворота — 1.7.0

- **Мачете:** исходная объёмная OBJ-модель с атласом, новый визуальный взмах по нативному `swingProgress`; урон/скорость атаки не дублируются дополнительными пакетами. В GUI сохранена исходная иконка.
- **Аптечка MCMOD:** удерживайте **ПКМ 2 секунды**. Исходная 3D-коробка, пять отдельных шприцев; при применении один извлекается/движется к поддерживающей руке. Лечение и расход выполняются **сервером только при завершении**. Отпускание кнопки, смена предмета и прерывание не расходуют шприц. Пять применений, пустая коробка и перерыв 5 секунд после успешного лечения сохранены. Текущий max HP не заменяется старой системой 1000 HP.
- Первое лицо: текущий скин Steve/Alex, правильный левый/правый рукав, зеркальная основная рука. Если другая рука занята, поддерживающая рука не добавляется. - **ИИ сущностей:** старое преследование/атака/брожение базового EntityMob восстановлены через задачи 1.12.2, а не оставлены неработающим наследованием. Исходные атрибуты сохранены. **Это ещё не утверждение полной эквивалентности:** чужая техника Flan/нестандартные контейнеры требуют своих API и интеграционных тестов. - Добавлены маленький/средний/большой рюкзаки, отдельный слот экипировки, специальный инвентарь на **9/18/27 доступных ячеек + хотбар**, сохранение, синхронизация, учёт `keepInventory` и исходные OBJ-модели рюкзаков на игроках.

**Компиляция не подтверждает визуальное совпадение.** Геометрия проверяется по исходному коду, но масштаб, положение, анимация и сетевое поведение ещё требуют запуска Minecraft.

## Управление

- **ПКМ** — стрелять. У автомата можно удерживать кнопку; полуавтоматическое оружие срабатывает при повторной активации использования предмета Minecraft.
- **R** или **Shift + ПКМ с оружием** — перезарядить. Новое оружие имеет пустой магазин; нужны подходящие патроны. В творческом режиме они не расходуются.
- **Левый Alt** (переназначается) — удерживать для увеличения при прицеливании. Для `svd`, `aim1` и ПСО подключены исходные прицельные маски.
- **Модуль в основной руке, оружие во второй:** ПКМ устанавливает модуль; Shift + ПКМ снимает модуль из соответствующего слота. Несовместимые модули не устанавливаются. В выживании заменённый модуль возвращается в инвентарь либо выпадает, если места нет.
- **Старая аптечка Flan:** ПКМ, +8 здоровья, 5 успешных применений; не тратится при полном здоровье. **Аптечка MCMOD** (`mcmod_aptech`): удерживать ПКМ 2 секунды, лечение до текущего максимума, 5 шприцев и перерыв 5 секунд.
- **Ремкомплект в основной руке, повреждённое оружие/броня во второй:** ПКМ полностью ремонтирует предмет. Комплект расходуется только при успехе.
- **Фильтр:** ПКМ при надетом подходящем противогазе/костюме; устанавливает запас 300 секунд. Запас расходуется всё время ношения, в том числе вне радиации.
- **Рюкзак:** ПКМ экипирует его и открывает инвентарь. В выживании **E** открывает специальный инвентарь; рюкзак снимается из отдельного слота.

### Гермоворота

Все шесть вариантов находятся во вкладке **«Декор»**; в инвентаре тоже отображается исходная объёмная модель. Ставьте ворота **за центр нижнего ряда**, а не за край:

- Подъёмные / открытые / правые: требуется полностью пустой участок **5 блоков шириной × 8 высотой × 1 толщиной**. Нижние 4 блока — проём, верхние 4 — карман подъёма.
- Левые / левые 45° / распашные OBJ: требуется пустой участок **7 × 4 × 7**, включая запас для поворота. По глубине он занимает 1 блок сзади и 5 спереди от центра. Это консервативная зона безопасности, а не размеры самой рамы. Сторона открытия зависит от ориентации установки.
- Камень, воздух с водой/растениями, чужие блоки или защищённая/незагруженная область в этой зоне отменяют установку **до расхода предмета**. Нужен обычный воздух. Зона движения резервируется невидимыми частями: их нельзя застраивать, но они не мешают ходить там, где нет самой створки/рамы.
- **Только сигнал редстоуна на любой части** — открыть; выключение сигнала — закрыть. ПКМ по раме/створке не переключает ворота.
- Подъёмные створки уходят вверх, левые и OBJ поворачиваются. С 1.7.0 все варианты начинают закрытыми: старые слова «открытые»/«45°» в названии не задают команду на открытие. При препятствии из живых существ движение приостанавливается.
- Разрушение любой части разбирает **только принадлежащую этим воротам** конструкцию. Служебные части не дают дополнительные предметы; в выгруженных чанках остатки удаляются после загрузки контроллера и частей.

Сначала проверяйте на копии мира. Не считайте наличие сетевого кода подтверждением игрового теста или совместимости со всеми сторонними системами защиты территории.

### Безопасность инвентаря

В отличие от старого кода, уменьшение рюкзака **не выбрасывает автоматически содержимое на землю**: вещи перемещаются в доступные ячейки, а оставшиеся видны в серых ячейках, из которых их можно забрать, но нельзя добавлять новые вещи. Shift-перенос в специальном инвентаре отключён, как в оригинальном контейнере. Полная интеграция ограничений вместимости с подбором предметов и другими контейнерами ещё не завершена. Перед проверкой мода в существующем мире сделайте резервную копию.

## Что ещё нужно для полного переноса

Актуальный список с привязкой к исходным классам: **[docs/FULL_PORT.md](docs/FULL_PORT.md)**.

Основные незавершённые части:

- Игровая проверка гермоворот: движение створок, коллизия, редстоун и поведение на границах чанков. Анимация и тайминги адаптированы, не побитовая копия старой реализации.
- Полная эквивалентность старой системы попаданий. Летящие пули, исходные хитбоксы и компенсация задержки реализованы; отдельная совместимость с чужой техникой требует её API.
- В исходной геометрии нет независимого магазина; извлечение магазина требует дополнительной модели/анимации. В 1.4.1 руки добавлены отдельно на стандартных мешах скина игрока; контакт кистей, положение модулей и движения требуют проверки в игре.
- Проверка ИИ, совместимости CustomNPC и нестандартных контейнеров, внешний ингредиент `fiberglass` для аптечки.
- Полноценная проверка клиента и выделенного сервера, включая сохранение, смерть, смену измерений и отсутствие дюпов.

**В исходных JAR отсутствуют OBJ вспышек `LastDays/models/sprites/SpriteShoot*`**, на которые ссылаются модели. Для точного воспроизведения нужны эти файлы; список — `docs/geometry-report.json`. Имитировать их наличие или объявлять перенос полностью готовым нельзя.

## Сборка и установка

Нужен **JDK 8**, не Java 17/21. Python для обычной сборки не требуется: ресурсы уже импортированы.

```sh
./gradlew --no-daemon build
# Windows: gradlew.bat --no-daemon build
```

Результат: `build/libs/metrocraft-port-1.12.2-1.12.0.jar`. Задача включает reobfuscation под обычный Forge. Workflow `.github/workflows/build.yml` также собирает JAR и публикует ZIP-артефакт `metrocraft-port-1.12.2`.

**Миры 1.7.10 автоматически не конвертируются.** У порта новые реестровые имена `metroport:*`; перенос сохранений требует отдельной миграции.

Распакуйте **JAR**, а не ZIP, в `mods` клиента и сервера Forge **1.12.2-14.23.5.2860**. Не устанавливайте старые JAR 1.7.10 рядом с новым модом. Папка `Flan` ему не нужна.
