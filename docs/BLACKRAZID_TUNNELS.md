# Все 19 исходных типов тоннелей — dev.10

Реализованы все **19 зарегистрированных классов тоннелей BlackRazid**:
159 исходных кубов круглой секции и **18 родных OBJ**, их MTL-привязки и 19 PNG-атласов.
Это не завершение всего расширения: транспорт, оружейные меши/анимации, прочий BlackRazid-декор
и игровой прогон остаются незавершёнными.

## Каталог и управление

Комплекты находятся во вкладке **«Декор»**. Один общий ID `metroport:blackrazid_tunnels`, варианты:

| Метаданные предмета | Секция |
|---:|---|
| 0 | Прежняя круглая секция, 159 кубов |
| 1 | Прежняя бетонная прямая секция |
| 2 | Бетонный поворот |
| 3 / 4 | Бетонная секция с деревянной обшивкой, два исходных варианта |
| 5 | Бетонная двойная секция |
| 6 | Бетонный выход |
| 7 / 8 | Бетонная секция с проводами / трубами |
| 9 | Бетонный перекрёсток |
| 10 | Новая секция TunnelNew |
| 11 / 12 | Металлическая прямая секция / поворот |
| 13 / 14 | Металлическая секция с деревянной обшивкой, два исходных варианта |
| 15 / 16 | Металлическая двойная секция / выход |
| 17 / 18 | Металлическая секция с проводами / трубами |

ПКМ устанавливает секцию по выбранной грани, поворот определяется направлением игрока.
Размер стека — 64 комплекта; удачная установка расходует ровно один, creative не расходует.
Секции не добываются обычным выживанием, как исходные неразрушаемые блоки; разрушение не возвращает комплект.
Копии мира dev.8/dev.9 сохраняют прежние значения **0 и 1**, типы не переиндексированы.
В мире тип хранится отдельным целым в tile NBT, поэтому варианты 16–18 не обрезаются четырьмя битами block metadata.
Pick Block возвращает правильный вариант, включая 18.

## Что сохранено из оригинала

- OBJ и PNG сохранены байт-в-байт. MTL-привязки сведены в `blackrazid_tunnel_mesh_materials.json`.
- Для всех четырёх направлений каждого OBJ записан **исходный порядок** translate/scale/rotate.
  Повороты и двойные секции не используют приблизительную матрицу прямого тоннеля:
  сохранены индивидуальные смещения до 17,16 блока и масштабы 0,988–0,993.
- Перекрёсток BetonX действительно имеет один и тот же исходный угол при всех четырёх metadata;
  ему не выдуман новый поворот. Четыре исходных выхода/секции с трубами рисуются двусторонними.
- Состояния cull, shade, normalize, цвет и привязка текстуры восстанавливаются после рендера.
  Меши разбираются один раз и очищаются при перезагрузке ресурсов.
- Граница видимости каждого OBJ вычисляется по всем исходным вершинам **после полного преобразования**.
  Большие повороты/двойные секции не должны исчезать из-за прежнего фиксированного куба ±9 блоков.
  Это проверка данных, а не подтверждение игрового frustum/reload-прогона.

## Коллизии и безопасность установки

Исходные OBJ-блоки **не имеют коллизии по поверхности меша**: только обычный якорный куб.
В порте не изобретена сплошная невидимая оболочка на всё изображение. Строитель карты должен подготовить место
и при необходимости отдельно задавать коллизию стен/пола. Круглая секция сохраняет свои 17 родных помощников:
кольцо уходит до шести блоков вниз, середина остаётся пустой.

Перед записью проверяются загруженность чанка, высота, граница мира, права и replaceable-блоки без чужих tile entities.
Проверяется исходный занятый блок/набор помощников, **не весь видимый объём OBJ**. Секции не роют проход в камне.
Ошибка записи откатывается без расхода предмета. UUID-владение не даёт удалить соседнюю конструкцию.
Клиент не размещает/не расходует комплекты; ни при проверке, ни при удалении не генерируются новые чанки.

## Важное исправление аудита «генераторов»

Восстановлены все шесть `ItemSpawnTunnel*`, но название вводит в заблуждение.
**В данном ModBase они вообще не зарегистрированы**, а их код не строит тоннель:
он делает ray trace на 5000 блоков и без проверки заменяет одну ячейку над целью на legacy ID.
Эти ID в предоставленном исходнике — **гермодверь, шкафы, стул, лавка и полка**, не тоннельные секции.
Исходный предмет не расходуется, нет серверных/защитных проверок и установки ориентации.

Поэтому эти классы не активированы молча и не названы «готовыми генераторами тоннелей».
Точный исходный класс/ID/назначение и SHA-256: [аудит](blackrazid-generator-audit.json).
Ранее заявленный остаток «шесть генераторов тоннелей» оказался ошибкой предварительного инвентаря;
перенос зарегистрированного мебельного/строительного набора остаётся в общем остатке.

## Проверки

Все 19 секций проверяются в четырёх направлениях: размещение/расход, NBT, собственник,
высокие metadata и Pick Block, отказ на занятых/защищённых/незагруженных ячейках, серверная сторона/ошибка записи.
18 OBJ проходят настоящий runtime OBJ-парсер без OpenGL; проверяются все группы/материалы и конечность координат.
Python дополнительно сверяет исходные байты, четыре последовательности трансформаций и попадание каждой вершины
в вычисленный render bounding box. Это **mock-тесты и проверки данных, не игровой прогон**.

Проверять в Minecraft нужно на копии мира: стыки/высоту, материалы с обеих сторон, соседство с обычными блоками,
повороты/двойные секции, дальнее отсечение, F3+T и отмену установки сторонними защитными модами.
