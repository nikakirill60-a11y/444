# Полный перенос: границы и критерии готовности

Запрос пользователя — полный перенос предоставленных JAR на 1.12.2, с исходными тремя вкладками и, по последнему запросу, отдельной четвёртой вкладкой «Декор». **В 1.11.0 интегрированы все зарегистрированные стволы/рабочие страницы модификаций MCMOD; полная игровая приёмка ещё не выполнена.** Этот документ не подменяет полный перенос списком уже добавленных предметов.

## Согласованные исключения

- **Не будет системы 1000 HP и точных старых формул защиты/износа брони.** Остаются обычное здоровье Minecraft и текущая адаптация брони порта; это не незавершённые задачи.
- **Снят прежний пункт 7 о недостающих ресурсах:** LastDays-вспышки, Barrett_Hazard, 25 отсутствующих текстур Exodus. Документированные заменители/ограничения остаются; поиск этих ресурсов не входит в план.
- Удалены стандартный режим инвентаря и переключатель сравнения. Основной инвентарь — Metro. Творческий каталог E оставлен только для выдачи предметов; I открывает экипировку.
- Последний запрос отменяет ограничение «только АК»: все 15 зарегистрированных стволов, исходные рабочие модули и GUI объединены в 1.11.0, не отдельными релизами. Незавершённые заглушки самого исходника перечислены в отчёте, а не выдаются за готовые функции.

## Зафиксированные ограничения ресурсов — не задачи на восстановление

LastDays/SpriteShoot…8, Barrett_Hazard и отсутствующие текстуры Exodus остаются документированными ограничениями. **По запросу пользователя их восстановление исключено**, ресурсы повторно не запрашиваются. Списки в geometry-report.json и exodus-report.json сохранены для прозрачности происхождения. Внешнего fiberglass для исходного рецепта аптечки также нет; выдуманный ингредиент не добавляется.

## Что означает «готов полный перенос»

1. Все строки с незавершёнными механиками реализованы или пользователь явно согласовал отличие.
2. Исходные ресурсы проверены на доступность и права; отсутствующие внешние зависимости перечислены, а не молча заменены.
3. Клиент и выделенный сервер реально запускаются на Java 8 / Forge 2860.
4. Пройден ручной сценарий `TESTING.md`, в том числе сетевые действия, сохранение, смерть, смена измерений и попытки дюпа.
5. Проверены визуальные масштабы и положение всех моделей, не только количество деталей в JSON.
6. Только после этого сборка называется полной, а не промежуточной.

Исходники для сверки восстановлены CFR 0.152 в `tools/legacy-reference`. Это справочные материалы 1.7.10; их наличие не означает, что старые классы автоматически работают на 1.12.2.

## Единая версия 1.11: оружие, модификации, часы

15 зарегистрированных стволов, 7 типов патронов; четыре рабочие страницы исходного ModMessage + RepairMessage. Оптика/коллиматор, глушитель, магазин 45/10/5, лазер; серверные цены/совместимость/атомарный возврат. Пневматика: 30 единиц, пороги урона 8/15/20, V — накачка. Сохранены исходные числа урона на ванильных 20 HP; старая отмена смерти исключена вместе с 1000 HP. Баллистика/NoDrop и расхождения с исходником: mcmod-firearms-report.json.

Ручная приёмка ещё обязательна: все предметы в первом/третьем лице, оба скина/руки, хват (прежний револьвер не изменён), все модификации и полный инвентарь, часы при всех видах перекладывания/закрытии/перезаходе, dedicated server. Автотесты не заменяют эти проверки.

В 1.11.1 по новым пользовательским скриншотам изменены третье лицо мачете/аптечки и предплечья оружия. Воспроизведён источник дюпа общих клиентских/серверных слотов (Entity ID equality + WeakHashMap), заменён слабой идентичностью объектов. ПНВ по ПКМ расходуется после creative-restoration vanilla. Новые регрессии/границы проверки: TESTING.md.
