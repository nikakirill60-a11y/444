# MinETRO Launcher — вход перед доступом, GitHub Releases, иконка

## Что изменилось

1. Сначала только регистрация/вход. Главная, настройки, папка сборок и операции
   установки/запуска закрыты до действительного сеанса и загрузки собственного
   профиля. После выхода или отказа авторизации доступ закрывается снова.
2. Вкладка «О сборке» удалена полностью.
3. По выбору пользователя создан новый **бесплатный** проект Supabase **MinETRO**,
   `xmhxucddhkitxqtweifu`. Старые четыре проекта не изменялись.
4. Добавлена оригинальная иконка: M, свод метро и рельсы. SVG/PNG/ICO есть в
   `launcher/MinETRO.Launcher/Assets`. В EXE встроены 9 размеров иконки.
5. Ручных каналов, URL-поля и выбора JSON нет. Автоматический источник — стабильные
   GitHub Releases `nikakirill60-a11y/444`; [формат публикации](../launcher/GITHUB_RELEASES_RU.md).
6. Надпись TEST, тестовый бейдж и кнопка входа через Prism убраны. EXE теперь
   `MinETRO-Launcher.exe`. Prism остаётся внутренним официальным движком Minecraft,
   не альтернативой профилю MinETRO и не способом обхода Microsoft-авторизации.

Старые каталоги настроек/данных с `Test` в пути намеренно не переименовывались,
чтобы не потерять пользовательские установки. В интерфейсе нет TEST 0.3.

## Что ещё требуется, без имитации готовности

**SMTP пока не настроен.** Подтверждение email включено, автоподтверждения нет.
Встроенная почта Supabase ограничена; рассылку произвольным пользователям нельзя
считать готовой. Требуется собственный SMTP в Supabase Auth, затем живой тест
регистрации → письмо → подтверждение → вход → скин → выход.

Текущий штатный путь подтверждения — ссылка из письма, затем «Вход» в лаунчере.
Landing на собственном Supabase не читает/не логирует токены и не содержит JS.
OTP/recovery-код в клиенте подготовлен, но скрыт флагом `emailCodesEnabled: false`:
сначала добавить `{{ .Token }}` в email-шаблоны и проверить доставку. Доступный
коннектор не имеет полей настройки SMTP, минимальной длины пароля и шаблонов;
эти параметры настраиваются в Dashboard. Клиент требует 12 символов; серверный
`password_min_length` пока стандартный 6 — перед публичным запуском выставить 12.

**Полный модпак ещё не опубликован** в GitHub Releases. Один JAR не подставлялся
вместо него. Игровой запуск и скины в Minecraft/для других игроков не проверены.

Регистрация — барьер штатного интерфейса, не DRM для публичных GitHub-файлов.
Пароли и сеансы не записываются на диск. Ключ в EXE/JSON только publishable,
привилегированные ключи и пароль БД в репозиторий не помещались.
