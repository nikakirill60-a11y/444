## Что сделано

- Schema 2: файлы и блоки по SHA256, без произвольных URL и ключей в манифесте.
- И загрузчик владельца, и лаунчер повторно передают только отсутствующие данные.
  Целые неизменённые файлы клиента не требуют сети даже без кеша блоков.
- Изменения собираются отдельно; проверка блоков и полных файлов, журнал, прежний
  экземпляр для отката. Резервные папки автоматически не удаляются.
- Неизвестные файлы игрока сохраняются. Удаляются только ранее управляемые файлы
  из новой копии. Config — seed-only. Миры, options, packv4 и mod_config защищены.
- Старые ZIP-экземпляры остаются отдельно, новая схема — MinETRO-dev-files.
- Publisher: Python 3.12+, drag-folder помощник PREPARE_UPDATE.cmd. Сначала
  подготовка, отдельно upload/dry-run, отдельно активация с подтверждением.
- Сервер выдаёт только активные блоки одобренным аккаунтам. История версий
  неизменяема; гонка публикаций, неполная загрузка и пустое подтверждение отклоняются.

## Доказательства и границы

14 Python-тестов; 12 новых протокольных/установочных сценариев C#; прежние
15 core + 12 accounts + 8 dev access + 6 release. Windows publish, WinForms smoke
с mock schema-2 релизом — PASS. Отдельно проверены серверные ACL и membership
для одобренного аккаунта в транзакциях с ROLLBACK; фикстуры в раздаче не оставлены.
JSON: `LAUNCHER_FILES_06_VERIFICATION.json`.

Миграция 202610300005 применена как подготовка протокола. **Активных релизов,
версий истории и объектов dev-packs — 0. Реальная сборка не включена.**
Первоначальная инспекция/перенос 3.71 ГБ, реальная загрузка publisher, квоты хостинга
и Minecraft ещё не проверены. Чанки 8 МиБ решают лимит одного объекта, но не общую
квоту хранилища. Изменение всего JAR/ZIP может потребовать всех блоков этого файла.
Локально новая копия пока создаётся целиком — экономится сеть, а не место на диске.
Первоначальная передача карты и миграции существующих конфигов требуют отдельного
решения после инспекции исходной сборки, это не часть обычных обновлений.

В ZIP есть `publisher/PUBLISHER_RU.md`: подготовка исходной распакованной папки
не требует нового полного ZIP и не выполняет публикацию. Секрет publisher нужен
только владельцу локально, никогда не передаётся в чат или лаунчер игроков.
Автоматического включения новых версий только по результату CI нет.
