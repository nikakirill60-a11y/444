# MWF Armory Studio v2.0 — программа без встроенных паков

Офлайн-программа для создания и настройки оружия/обвесов контент-пака Minecraft 1.12.2, под выбранный закрытый `modularwarfare-shining-2024.2.4.6f-fix1.jar`. Основной JAR не изменяется; companion/bridge-мод не нужен.

## Скачать и запустить

[MWF_Armory_Studio_v2.zip](https://raw.githubusercontent.com/nikakirill60-a11y/444/arena/dcab859f-444/downloads/MWF_Armory_Studio_v2.zip)

1. Распаковать архив в отдельную папку.
2. Открыть **MWF_Armory_Studio.html** в современном Chrome/Edge/Firefox с WebGL2.
3. Всё работает локально: сервер, установка Node/Java и интернет не нужны.
4. Полная инструкция — `ИНСТРУКЦИЯ.txt` внутри архива, исходный текст — [README_RU.txt](../tools/mwf-armory/README_RU.txt).

Архив: **207 852 байта**. SHA-256:

```text
7be73b296e06e27f76128fc042caf5ba7aa36e9970a66d7a16cafcfe9d051298
```

HTML содержит только Three.js, fflate и интерфейс программы. **Оружия, моделей, текстур, звуков и контент-паков в дистрибутиве нет.** Нет чтения ZIP Убойника/Дуплета при сборке и нет base64 встроенного пака. HTML — 734 591 байт; в архиве только HTML, инструкция и лицензии. Загрузки со сторонних CDN нет. Загружаемые пользователем ресурсы сохраняют свои авторство и лицензии.

## Что изменилось в v2

- Пустой старт: нажмите **«Открыть свой ZIP» / «Открыть проект»** или восстановите своё сохранение из браузера. Пушки не подгружаются автоматически.
- Убраны программные пороги 64 МБ для ZIP, 160 МБ распакованных данных, 10 000 файлов, 95 МБ файла проекта и 90 МБ base64 проекта. Нет этих порогов ни на импорте, ни на экспорте, ни при восстановлении проекта.
- Это не бесконечная память: остаются реальные ограничения RAM/массивов/JSON/WebGL браузера и квота IndexedDB. Не открывайте недоверенные ZIP: сильно сжатый архив может исчерпать память. Большие проекты сохраняйте файлом.
- Проверки безопасных путей, форматов, конечных чисел и совместимости MWF сохранены. Ограничения геометрии OBJ/разрешения PNG и требования mono OGG — отдельные проверки, не лимит объёма ZIP/проекта.
- До открытия совместимого пака инструменты редактирования/экспорта выключены; открытие файлов и восстановление проекта доступны.
- В смешанном паке автоматически выбирается поддерживаемое оружие с внутренним боезапасом. Магазинные/неподдерживаемые пушки явно помечены и сохраняются при экспорте без редактирования. Поддержка магазинных механик **не добавлена** снятием лимитов.
- Предпросмотр учитывает `defaultHidePart` / `hidePart` / `showPart` нативных модулей, допускает штатный нулевой масштаб их внешней модели и переиспользует атлас обвесов вместо повторной загрузки каждой его копии.

## Что реализовано

| Раздел | Возможности |
|---|---|
| Арсенал | Новые уникальные ID/названия, копирование Enhanced-шаблона, несколько пушек в одном проекте, открытие совместимого ZIP |
| Параметры | Урон за пулю/дробину, их число, бонус в голову, дальность, разброс, RPM, semi/full/burst, длина очереди, отдача/рандомная отдача, скорость движения, внутренний боезапас |
| Перезарядка | Время в секундах с пересчётом native Enhanced-фаз, а не только изменение server `reloadTime` |
| OBJ | Парсинг вершин/UV/нормалей, отрицательных индексов, триангуляция плоских n-gon; выбор оси ствола, длины и центрирования; преобразование в embedded-buffer glTF |
| Несколько PNG | Одновременное использование материалов, MTL `map_Kd` + ручное назначение, единый PNG-атлас с защитными краями, корректные UV для glTF и OBJ |
| Положение | Руки отдельно по сторонам, normal/slim, idle/reload; модель отдельно от рук; всё оружие в кадре, HIP/ADS; orbit/FP, FOV/формат кадра |
| Обвесы | Создание отдельных предметов из OBJ/PNG, barrel/sight/grip/stock/laser, совместимость, default-установка, смещения/углы/масштаб, нативные множители/глушитель/вспышка, смещение ADS и zoom прицела |
| Патроны | Копирование существующего loose-round патрона в независимый предмет, назначение пушке, имя/стак/множители урона и точности/slug; гильза и иконка наследуются |
| Ресурсы | PNG пушки, иконка PNG или снимок модели без рук/фона, mono OGG Vorbis на выбранное событие, прослушивание |
| Проекты | Файл `.armory-project.json` со всем паком и текущими незапечёнными правками; дополнительное сохранение в IndexedDB; Undo/Redo параметров и поз |
| Экспорт | Полный ZIP всех пушек, обвесов, патронов и ресурсов; сериализация gun JSON, render JSON и glTF, обновление русских/английских локализаций; проверка ссылок на патроны/обвесы |

### Типовой путь

**Открыть свой ZIP → Арсенал → копия шаблона → OBJ/MTL/PNG → Параметры → Руки/ADS → Обвесы → Ресурсы → Сохранить проект → Экспорт ZIP.**

Переключение пушки сохраняет её параметры и запекает её текущие смещения в проекте. Оно не предлагает сбросить предыдущую пушку, как старый редактор рук. Повторный экспорт/восстановление проекта не должен повторно применять уже запечённое смещение: этот сценарий проверен в браузерном тесте.

Создание, импорт ресурсов и переключение пушек — границы истории Undo. Они не являются поводом полагаться только на Undo: сохраняйте резервные файлы проекта.

## Патроны на модели

Импорт распознаёт отдельные OBJ-группы `bulletModel_0`, `bulletModel_1`, …; их видимость зависит от числа оставшихся патронов. Кнопка выстрела в предпросмотре уменьшает число на один. Если патроны слиты с корпусом, автоматического надёжного разделения нет. Корпус должен присутствовать как обычная группа. Необязательная группа `flashModel` преобразуется отдельно; остальные группы объединяются в `gunModel`.

Пушка без таких групп, включая исходный Дуплет, не получает фиктивную визуальную «убыль патронов». Импорт не добавляет новых механик MWF и не разделяет слитую модель на движущиеся детали.

## Ограничения форматов и предпросмотра

- Это редактор контент-паков, не реализация любых механик MWF. Новая Java-логика, полноценные магазинные системы, произвольные кости/шарниры/редактор ключей анимации не созданы.
- Новые OBJ импортируются в проверенный rigid Enhanced-шаблон с его руками/действиями. Анимация нового затвора, перелома стволов или барабана автоматически не генерируется.
- Открытие существующих паков: текстовый glTF с встроенными буферами и стандартными отдельными узлами рук. BASIC-пушки, GLB, skeletal skin/joints и внешние glTF-буферы не поддерживаются.
- Импорт не ограничен только готовыми glTF: новый OBJ преобразуется в такой шаблон. Это отличается от открытия готового BASIC-пака.
- Несколько **разных** PNG требуют UV 0..1. Для повторяющихся UV нужна предварительная запеканка в Blender; при одном PNG tiling сохраняется и байты PNG не меняются.
- До 8 PNG, PNG/атлас до 4096²; OBJ до 20 МБ/180 000 треугольников. Геометрия режется на индексированные 16-битные примитивы, а не переполняет индексы.
- PBR/normal/emissive/MTL opacity не запекаются. PNG-прозрачность базовая. Неидеальные/неплоские n-gon желательно триангулировать заранее.
- Отдельное смещение mesh отключено для модели с собственными анимационными каналами деталей, чтобы не затирать их. Положение всей пушки остаётся доступным.
- Предпросмотр — Three.js, **не Minecraft**: полноценная отдача/баллистика, PIP/сетка/стекло прицела, эффекты ЛЦУ, OptiFine, освещение и коллизии не эмулируются. Настройка zoom сохраняется в конфиге, но увеличение в сцене не симулируется.
- OGG должен быть mono Vorbis: MP3/WAV, Opus и stereo отклоняются. Конвертера звука нет.
- Искусственных порогов размера ZIP/проекта и числа файлов больше нет. Безопасные пути проверяются при чтении записей ZIP до распаковки соответствующей записи; рабочее пространство остаётся в памяти браузера.
- Сохранённый NBT старых предметов не мигрируется. Перед уменьшением ёмкости разрядите оружие в игре.
- Minecraft/Forge в песочнице **не запускался**. Проверки ниже не заменяют испытание в реальном клиенте/на сервере. OpenGL 1281 редактор не исправляет.

## Установка результата

Полностью закрыть Minecraft, убрать прежние паки/папки с совпадающими ID и положить экспортированный ZIP **целиком** в `ModularWarfare/`. На сервере нужен такой же ZIP. Основной MWF JAR оставить.

Если остался старый рабочий 4-патронный Дуплет: сначала разрядить его, затем удалить **только** `metro-duplet-bridge*.jar` из mods клиента/сервера. В самой программе никакого Дуплета нет; свойства оружия приходят только из вашего загруженного пака.

## Исходники и сборка

Отдельная программа: `tools/mwf-armory/`. Не меняет исходники/распространяемый ZIP старого Pose Editor. Математика поз и их запекания перенесена в собственный `core.mjs`, чтобы новая программа собиралась независимо; регрессионные тесты перенесены вместе с ней.

```bash
npm ci --prefix tools/mwf-armory --no-audit --no-fund
npm test --prefix tools/mwf-armory
npm run build --prefix tools/mwf-armory
```

Результаты: `artifacts/mwf-armory/index.html`, `downloads/MWF_Armory_Studio_v2.zip`. Зависимости и большие проверочные экспорты не включены в Git. CI `.github/workflows/mwf-armory.yml` запускает 50 тестов, собирает HTML и прикладывает архив.
