## Что исправлено в v3

- **Все 23 пушки полного арсенала доступны для редактирования**, вместо четырёх. Отъёмные магазины больше не являются причиной блокировки.
- **BASIC/OBJ открывается и экспортируется в родном формате.** Нет скрытой подмены BASIC на Enhanced. Параметры рук редактируются в `arms.leftArm/rightArm`: `armPos`, `armRot`, `armReloadPos`, `armReloadRot`, `armScale`. Положение оружия — родной `aim`.
- Для показа BASIC OBJ строится временный индексированный glTF и процедурные стандартные боксы рук. Этот glTF не записывается в экспорт. Собственные именованные OBJ-группы сохраняются.
- **Enhanced/glTF с магазинами:** баланс, руки, HIP/ADS, импорт модели, ресурсы, обвесы, проекты и экспорт работают так же, как для внутреннего боезапаса.
- Перезарядка магазина — один цикл PRE/FIRST/SECOND/POST, а не повтор цикла по числу патронов. Пересчитываются native Enhanced-фазы; для BASIC меняется `reloadTime`, исходная Java-анимация сохраняется.
- Магазин: имя, ёмкость, `magazineCount`, пустые магазины, множители перезарядки, `subAmmo`, совместимость `acceptedAmmo`, default-магазин. Выбор магазина для настройки/просмотра не превращает пушку в поштучную.
- Копирование магазина сохраняет исходные модели/скины/иконку, создаёт независимый ID. Параметры предмета магазина общие для всех пушек с этим ID — интерфейс об этом предупреждает.
- Создание патрона для магазинной пушки меняет **`subAmmo` выбранного магазина**, не добавляет ей неуместный `acceptedBullets`.
- Импорт OBJ/PNG выбранного магазина; положение магазина на текущей пушке. Enhanced — `attachment[id]`, BASIC — `maps.ammoMap[id].offset/scale`. Динамический OBJ-магазин загружается в просмотр из пака.
- При создании копии оружия сохраняются формат и система боепитания шаблона.
- Undo/Redo включает JSON магазинов; проекты сохраняют все магазины/патроны и выбранный магазин для просмотра. Формат проекта остаётся `version: 1` для совместимости со старыми проектами.
- Одна внешняя папка ZIP распознаётся. Внешние метаданные сохраняются под `_archive_metadata/`. Несколько отдельных паков требуют раздельного открытия. Архив программы и ZIP только с исходными OBJ/PNG получают отдельные понятные сообщения.
- В историческом арсенале встречается `fireModes: auto`; выбранный JAR сериализует FULL как **`full`**, а не `auto`. При экспорте редактор исправляет этот legacy-режим во всех пушках пака. Исходный ZIP на диске не меняется.

## Что сохранено

Параметры оружия/урон/RPM/отдача/дальность; отдельное положение рук и модели; HIP/ADS и orbit; создание оружия на основе собственного шаблона; импорт OBJ/MTL и нескольких PNG одновременно в атлас; пять слотов обвесов, совместимость/default/игровые множители; PNG пушки, иконка или снимок, mono OGG Vorbis; копирование патронов; файл проекта, IndexedDB, экспорт полного ZIP и локализации.

После загрузки своего пака: **Арсенал → выбранная пушка или копия → OBJ/модель → Параметры → Руки → Обвесы/Ресурсы → Сохранить проект → Экспорт ZIP**. Переключение оружия сохраняет его правки в рабочем паке; уже запечённые смещения повторно не применяются. Импорт ресурсов, создание предметов и переключение — границы Undo; храните резервные файлы проекта.

Из v2 сохранены пустой старт и отсутствие порогов 64/160/95 МБ, 90 МБ base64 и 10 000 ZIP-записей. Реальный предел — RAM/JSON/массивы/WebGL и квота IndexedDB, не бесконечная память. Проверки безопасных путей и форматов не отключены. Не открывайте недоверенные ZIP.

## Границы поддержки

- BASIC-пак должен содержать `guns/*.json`, `guns/render/*.render.json`, `obj/guns/*.obj` и скины. ZIP только с OBJ/PNG не является готовым MWF-паком: откройте свой пак-шаблон, создайте копию и импортируйте геометрию. У BASIC требуется группа `gunModel`; именованные части сохраняются.
- **BASIC-перезарядка в просмотре схематична**, между обычной/reload-позами. Это не эмулятор Java-состояний помпы, затвора, барабана, смены секций магазина и прочих действий. Родные настройки сохраняются для игры. Визуальные индексированные патроны зависят от возможностей конкретного native-рендера; наличие группы само по себе не добавляет механику BASIC.
- Enhanced требует текстовый glTF со встроенными буферами. GLB, внешние буферы и skeletal skin/joints пока не поддерживаются. Нет отдельных узлов руки — недоступно изменение именно этой руки, а не всей пушки.
- Новые шарниры/кости и ключи анимации автоматически не создаются. Для уже анимированных деталей отдельное mesh-смещение отключается, чтобы не затирать каналы; положение всей пушки остаётся доступным.
- OBJ до 20 МБ / 180 000 треугольников; до 8 PNG, PNG/атлас до 4096². Несколько разных PNG требуют UV 0..1; при одном PNG tiling сохраняется. PBR/normal/emissive/MTL opacity не запекаются.
- Предпросмотр — Three.js, не Minecraft: PIP/сетка прицела, полноценная баллистика/отдача/коллизии/свет/OptiFine не эмулируются. Новая Java-механика не появляется от редактирования конфига. OpenGL 1281 программа не исправляет.
- Перед уменьшением ёмкости разрядите предметы в игре: старый NBT не мигрируется. Закройте Minecraft, уберите прежние паки с совпадающими ID, установите экспортированный ZIP целиком в `ModularWarfare/`; серверу нужен такой же ZIP.
- **Minecraft/Forge не запускался.** Проверки браузера/схем/библиотеки JAR не заменяют проверку в клиенте и на сервере.

## Сборка и повторение проверок

```bash
npm ci --prefix tools/mwf-armory --no-audit --no-fund
npm test --prefix tools/mwf-armory
npm run build --prefix tools/mwf-armory

PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs MWF_CHROMIUM=/path/to/chromium \
  node tools/mwf-armory/browser-smoke.mjs
PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs MWF_CHROMIUM=/path/to/chromium \
  node tools/mwf-armory/browser-formats.mjs
python tools/mwf-armory/verify_export.py artifacts/armory-v3-mag-export.zip \
  --mwf-jar /path/to/selected.jar --jvm /path/to/libjvm.so
```

Для JVM-проверки нужен JPype1. Результаты сборки: `artifacts/mwf-armory/index.html`, `downloads/MWF_Armory_Studio_v3.zip`. CI запускает Node-тесты, собирает офлайн-HTML и прикладывает ZIP. Старые дистрибутивы v1/v2 и файлы арсенала оставлены без изменений.
