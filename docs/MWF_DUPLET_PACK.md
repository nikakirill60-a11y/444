## Установка

1. Сделать резервную копию мира и старого пака **вне** папки ModularWarfare. Полностью закрыть Minecraft.
2. Убрать старый `Metro_Uboinik...zip` и распакованные дубликаты. **Новый ZIP уже включает Убойник v5** — два пака с одинаковыми предметами одновременно не устанавливать.
3. Положить `Metro_Uboinik_Duplet_MWF_fix1_v1.zip` **целиком** в `.minecraft/ModularWarfare/`.
4. Положить `metro-duplet-bridge-1.0.0.jar` в `.minecraft/mods/`, рядом с неизменённым выбранным MWF fix1.
5. На выделенном сервере установить тот же контент-пак и переходник. Рекомендуется одинаковая сборка клиента/сервера. Логика переходника серверная, собственного сетевого протокола нет.
6. Запустить игру заново. Открыть штатное меню модификаций MWF для установки обвесов.

Без переходника это два статических варианта оружия: установка/снятие обычного обвеса сама вместимость не меняет. Редактор также не заменяет переходник: экспортирует ZIP ресурсов, **не JAR**.

## Предметы и поведение

- `modularwarfare:metro_duplet` — Дуплет, вместимость **2**.
- `modularwarfare:metro_duplet_4` — вариант на **4**, модуль «+2» по умолчанию. Вариант также доступен в креативе.
- `modularwarfare:metro_duplet_extra_barrels` — съёмные **+2 ствола**.
- `modularwarfare:metro_duplet_suppressor` — глушитель.
- `modularwarfare:metro_duplet_long_barrel` — удлинитель.
- `modularwarfare:metro_duplet_grip` — рукоять.
- `modularwarfare:metro_duplet_stock` — приклад.
- Боеприпас общий с Убойником: `modularwarfare:metro_12g_buckshot`.

«+2», глушитель и удлинитель занимают **один слот barrel**, поэтому взаимоисключающие. Рукоять — grip, приклад — stock. Это не автоматическое переключение анимации хвата по цевью: такой логики нет.

Один выстрел расходует один патрон и выпускает 8 дробин. Стартовый баланс адаптирован: 3 базового урона на дробину, 150 RPM. Номинальная полная зарядка — 3 секунды для двух патронов, 4,8 секунды для четырёх; частичная короче. Времена настроены и в серверном таймере, и в Enhanced-фазах. Это не восстановленные оригинальные ТТХ и не измерение времени в запущенной игре.

## Переходник: безопасное ограничение v1

**Любые изменения обвесов Дуплета — только при `ammocount=0`, вне активной перезарядки/выгрузки.** Сначала полностью разрядить штатным действием MWF. Загруженный Дуплет не меняется; автоматического возврата «лишних двух» в v1 нет.

Переходник использует отменяемые штатные `WeaponAttachmentEvent.Load/Unload` выбранного JAR. Установка/снятие выполняется транзакционно на копиях инвентаря и курсора:

- проверяет конкретное оружие, принадлежность входящего предмета, пустую камору, отсутствие серверных reload-задач;
- расходует ровно один входящий обвес, возвращает снятые детали;
- при нехватке места отказывает **до изменений**, ничего не выбрасывая;
- меняет **конкретный ItemStack** между двумя зарегистрированными вариантами, сохраняя сериализованный NBT, skinId, метаданные и ForgeCaps;
- проверяет точное соответствие сериализованных данных после конструирования нового ItemStack; если данные не сохраняются, отказывает;
- откатывает слоты при исключении записи;
- не меняет общий `GunType.internalAmmoStorage`, не затрагивает чужие пушки/игроков, не патчит MWF через coremod/ASM.

## Модель и ограничения

MTL показывают `wpn_duplet.2048.png` для основного оружия, +2, удлинителя, рукояти и приклада → используются оригинальные **texture.png**. MTL глушителя ссылается на `wpn_obves.2048.png` → оригинальная **obvestexture.png**. PNG сохранены байт-в-байт, названия объектов глушителя/удлинителя нормализованы в `attachmentModel`, грани триангулированы.

Исходный gunModel слитный. **Полноценная анимация переломки, экстракция гильз и видимые исчезающие патроны для Дуплета не восстановлены**: отдельных исходных деталей/анимаций нет. Модель не разрезалась произвольно для выдуманного шарнира. Базовые движения адаптированы из проверенного Enhanced-пайплайна, хват рассчитан по рукояти/цевью, обычное положение подстроено под более короткий Дуплет. Четырёхствольный вариант имеет дополнительное понижение ADS для верхней пары стволов. Поза стартовая и требует игровой проверки.

Звуков Дуплета в загрузке нет: временно используются исходные звуки Убойника, с сохранением их байтов и авторства.

Редактор v2 показывает три варианта оружия, пять обвесов Дуплета, их взаимное исключение, 2/4/6 зарядов и соответствующие длительности. Оба Дуплета используют один glTF: экспорт правок рук затрагивает оба варианта, смещение всего оружия — конфиг выбранного варианта. Флажки обвесов — только предпросмотр, не установка на игровой предмет.

**Minecraft здесь не запускался.** Совместимость переходника с полным модпаком/сторонними capabilities, игровая синхронизация, руки/ADS, TP, посадка всех обвесов и звук требуют проверки в игре. Браузер не воспроизводит освещение/отдачу/покачивание Minecraft. OpenGL 1281 не исправлен. Тесты не являются доказательством отсутствия всех дюпов в реальном модпаке.

## Выполненные проверки

- **43 Python-теста:** прежние 34 Убойника плюс 9 Дуплета; текстуры/MTL, ёмкость, оба таймера reload, сохранение старого пака, индексы/геометрия, полный camera/frustum при FOV 50/70/90 и ADS 0/0,5/1, отсутствие ложной переломки, TP-иконки, байтовая воспроизводимость ZIP.
- **26 Java-тестов переходника:** установка/снятие 2↔4, расход/возврат, загруженное оружие, два типа reload-блокировки, чужой игрок/оружие, полный инвентарь, курсор, замена стволов, unload-all, NBT/метаданные/ForgeCaps, отсутствующий вариант, серверная авторитетность, MCP/SRG fallback, 50 циклов, откат при ошибке записи, некорректное количество сохранённых обвесов.
- **20 Node-тестов** экспортера редактора сохранены и проходят.
- Проверены **настоящие схемы и отменяемые события выбранного JAR**, а не только исторический Java-исходник. Его `GltfModelReader` читает Дуплет: **7 узлов, 6 мешей**. Пак — **82 файла**, всего 12 предметов (5 прежних + 7 новых). Старые ресурсы/конфиги Убойника v5 неизменны, кроме дополненных четырёх языковых таблиц.
- Chromium 153/SwiftShader: одиночный HTML открыт через `file://` с блокировкой HTTP, все варианты/обвесы, ADS/осмотр, правки рук, undo/redo, скачивание/импорт проекта и реальный экспорт ZIP. Нет ошибок страницы и HTTP-запросов; скриншоты просмотрены. Экспортированный из браузера ZIP (83 файла с журналом редактора) отдельно прошёл проверку выбранным JAR.

Java-тесты используют настоящие классы `WeaponAttachmentEvent` из выбранного JAR, но Minecraft/Forge заменены **тестовыми двойниками ABI**. Они не входят в готовый мод. JAR содержит только **2 собственных Java-8 class-файла** (major 52), метаданные и инструкцию; чужие игровые классы не поставляются.

## Сборка

```sh
PYTHONPATH=.cache/mwf-audit/python python tools/build_duplet_pack.py
python tools/build_duplet_bridge.py --java PATH/TO/java --ecj PATH/TO/ecj.jar --boot PATH/TO/java8-api.jar --mwf PATH/TO/original-fix1.jar
cd tools/mwf-pose-editor
npm ci
npm test
node build.mjs --duplet
```

Для Python нужны `tools/requirements-mwf-pack.txt`; commit исходников должен быть доступен через Git. В ограниченной среде использованы Java из jdk4py, ECJ из `processing/processing:java/mode/org.eclipse.jdt.core.jar` и **compile-only** Java-8 mock API из `JetBrains/intellij-community:java/mockJDK-1.8/jre/lib/rt.jar`. Компилятор/boot API не включены в поставку:
- ECJ SHA-256 `34c8befa030343a93a2658cff45e79fd4b4742845281c87da5f65144b38bade0`;
- boot API SHA-256 `95171c4e778b668bce9b6a143284de35ff039ed7c3f3474eeaa7bc1dfa7a91ae`.

Проверка: `tools/verify_duplet_pack.py PACK --mwf-jar ORIGINAL_JAR --jvm PATH/TO/libjvm.so`. Необязательный браузерный smoke: `tools/mwf-pose-editor/browser-duplet-smoke.mjs`, требует playwright-core и переменной `MWF_CHROMIUM` с путём к Chromium.
