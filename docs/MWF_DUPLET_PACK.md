# Дуплет v2 — без дополнительного мода, «+2 ствола» только декор

По решению пользователя рабочая модификация ёмкости **отменена**. Дополнительный `metro_duplet_bridge` не используется и не поставляется. Основной закрытый MWF fix1 не изменён.

## Скачать и установить

**[Общий контент-пак «Дуплет v2 + Убойник v5», ZIP, 11,05 МБ](https://raw.githubusercontent.com/nikakirill60-a11y/444/arena/dcab859f-444/downloads/Metro_Uboinik_Duplet_MWF_fix1_v2.zip)** — это один обычный контент-пак, не внешний установочный архив. Положить **целиком** в `.minecraft/ModularWarfare/`, не распаковывать.

Если уже была установлена предыдущая версия:
1. **До обновления** полностью выгрузить патроны из старых Дуплетов штатным действием MWF. Сделать резервную копию мира/пака отдельно от ModularWarfare.
2. Полностью закрыть игру.
3. **Удалить `metro-duplet-bridge-1.0.0.jar` из `mods/` клиента и сервера**, если он был установлен. Основной `modularwarfare-shining-2024.2.4.6f-fix1.jar` оставить.
4. Убрать старые ZIP Убойника/Дуплета и распакованные дубликаты с теми же ID. Новый ZIP уже включает Убойник v5 — старый рядом не оставлять.
5. Установить новый ZIP; на сервере нужен такой же. Полностью перезапустить игру.

Удаление JAR из этой репозитарной поставки **не удаляет файл с компьютера пользователя** — ранее установленный мод нужно убрать вручную.

## Текущее поведение

- Обычный Дуплет: **2 патрона**.
- Дополнение `metro_duplet_extra_barrels` можно устанавливать/снимать как обычный barrel-обвес MWF.
- **«+2 ствола» — только визуальная модель:** ёмкость остаётся **2**, дополнительных выстрелов, дробин, урона, скорости или ускорения перезарядки не появляется. Настройки barrel у этого обвеса нейтральные: isSuppressor=false, hideFlash=false, accuracyFactor=1; множители отдачи по умолчанию 1.
- Глушитель, удлинитель, рукоять и приклад сохранены. «+2», глушитель и удлинитель занимают один слот barrel и взаимоисключаются. Рукоять — grip, приклад — stock.
- Боеприпасы общие с Убойником: `modularwarfare:metro_12g_buckshot`.
- Убойник v5, его таймер 8 с, модель/текстуры/поза и конфигурации не менялись. Дополнены только четыре языковых таблицы общего пака.
- Смена обвесов теперь полностью штатная механика MWF. Специальные проверки разряженности, серверные транзакции, переключение ItemStack и защита заполненного инвентаря из отменённого переходника **не выполняются**. Их не следует приписывать текущему паку.

### Совместимость со старым предметом

ID `modularwarfare:metro_duplet_4` сохранён, чтобы не удалять существующие предметы из мира. Теперь он называется **«Дуплет (+2 ствола, декор)»**, имеет вместимость **2**, номинальную полную зарядку **3 секунды** и декоративный модуль по умолчанию. Это не рабочая четырёхстволка. Основной Дуплет тоже имеет 2 патрона и 3 секунды.

ZIP-конфигурация **не переписывает NBT уже существующих предметов**. Если в старом предмете осталось `ammocount=4`, оно не урезается автоматически: **перед обновлением выгрузить эти патроны**. Автоматический мигратор не добавлялся, поскольку дополнительный мод отменён.

## Редактор рук

[Редактор v3 с косметическим паком — ZIP, 11,50 МБ](https://raw.githubusercontent.com/nikakirill60-a11y/444/arena/dcab859f-444/downloads/MWF_Pose_Editor_v3_Duplet_Cosmetic.zip). Распаковать отдельно от Minecraft, открыть `MWF_Pose_Editor.html` в современном браузере. Интернет не нужен.

Оба Дуплета в новом предпросмотре имеют максимум **2**, таймлайн полной зарядки **3 с**; визуальные флажки обвесов работают по-прежнему. Убойник — 6 зарядов. Экспорт содержит текущий косметический пак без JAR. Оба Дуплета используют один glTF: правки рук применяются к обоим, смещение всего оружия — к конфигу выбранного варианта.

Старый редактор v2 и сохранённые проекты со встроенным старым паком 2/4 не использовать как источник новой сборки: они содержат старые конфиги. Новые проекты начинать из редактора v3/нового ZIP.

## Что убрано и что сохранено

- Из активных загрузок удалены прежние JAR переходника, v1-пак, v1-установщик с модом и редактор v2 со старым рабочим вариантом 4. Внешний установщик и `tools/build_duplet_install.py` больше не нужны: достаточно одного ZIP контент-пака.
- Исходник отменённого переходника и его тестовые двойники оставлены **только для истории**. `tools/build_duplet_bridge.py` по умолчанию отказывает в сборке; архивная сборка требует явного `--enable-legacy-bridge` и пишет в `artifacts/legacy-duplet-bridge/`, а не в downloads. Для текущего пака её не устанавливать.
- Модели, текстуры, поза и обвесы сохранены. Источник — `Дуплет/` из `main`, commit `ce2783694767296a102221f69f622d35264924e4`. Основная texture.png используется для оружия/+2/удлинителя/рукояти/приклада, obvestexture.png — для глушителя, по MTL. Исходное авторство не меняется.
- Полноценная переломка, экстракция и видимые отдельные патроны не восстановлены. Звуки Дуплета пока от Убойника. OpenGL 1281 не исправляется.

## Проверки этой версии

- **47 Python-тестов:** прежние 34 Убойника, 9 проверок Дуплета, обновлённых на две ёмкости по 2, и 4 новых проверки: нейтральность декоративного обвеса/одинаковые ТТХ, отсутствие мода/кода в поставке, отказ архивного сборщика без явного включения, инструкция по сохранению старых патронов. Проверяется воспроизводимость ZIP.
- **20 Node-тестов** экспортера редактора проходят.
- Проверка схем по выбранному настоящему fix1 JAR и чтение его `GltfModelReader`: Дуплет **7 узлов, 6 мешей**, общий пак **82 файла**, без JAR/class; старые ресурсы Убойника v5 сохранены.
- Chromium 153/SwiftShader, реальный одиночный HTML через `file://`: проверены три оружия с максимумами **2/2/6**, декоративный +2 по умолчанию у совместимого ID, взаимоисключение стволов, рукоять/приклад, 3-секундный таймлайн, ADS/осмотр, правки рук, undo/redo, проект и экспорт ZIP. Нет ошибок страницы и HTTP-запросов. Экспорт из браузера отдельно проверен выбранным JAR: **83 файла** с журналом редактора, всё ещё 2 патрона и без мода.

**Minecraft здесь не запускался.** Проверки не доказывают совпадение игрового рендера, совместимость с полным модпаком или отсутствие ошибок штатного MWF. Отменённые 26 Java-тестов переходника относятся к исторической логике, а не к текущей поставке.
