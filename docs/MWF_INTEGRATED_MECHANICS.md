# Встроенные механики Metro MWF 1.3

Пользователь разрешил изменить выбранный закрытый MWF: накачка оружия, рабочие дополнительные
стволы Дуплета и звуки глушителей. Это отменяет прежнее решение о чисто декоративных +2 стволах.

## База и архитектура

- Входной MWF: ровно предоставленный `modularwarfare-shining-2024.2.4.6f-fix1.jar`,
  SHA-256 `f91a5419cbc9e3cbd18f831e37c17aa2833d577142d324fed1ca14846ce95183`.
- Пак: опубликованный v2 compatibility, SHA-256 `87a1c12a14543b022810da233d8db26548e7587d7b9cd804bd155712e624f6ec`.
- Нет переключения на другую версию публичного upstream. Сборщик меняет точечные места
  в **копии этого JAR**, сохраняет остальные классы, ресурсы, лицензии и существующий bootstrap.
- Дополнительный bridge/coremod не устанавливается. Исходный JAR не перезаписывается.
- Версия Forge-мода получает суффикс `-metro3` и строгую проверку версии второй стороны:
  исходный клиент не должен отправлять неизвестные новые пакеты изменённому серверу и наоборот.

`PatchMwf.java` выполняется только при сборке на JDK 17. В Minecraft поставляются helper-классы
Java 8 и изменённые исходные классы MWF, а не сборочный ASM-инструмент или тестовые заглушки.

## Реализованные правила

Удерживание **P**, переназначаемое в управлении: +20 давления/энергии каждые 10 серверных тиков.
Клиент отправляет только номер хотбар-слота. Сервер сам проверяет оружие, наличие персонажа,
выбранный слот, боезапас, перезарядку, время накачки и интервал запросов. Состояние находится
в NBT конкретного оружия, сохраняется при выбрасывании/загрузке мира, не зависит от магазина.
Накачка не добавляет патроны. Первоначально давление/заряд равны нулю.

- **Тихарь:** максимум 120, расход 8 на выстрел.
- **Хельсинг:** максимум 120, расход 18 на выстрел.
- Нормальное давление 100; превышение теряет 1 единицу/сек до 100. Урон зависит от давления,
  избыточное давление даёт до +20%. При нехватке воздуха выстрел блокируется.
- **Рельса:** 100 энергии, расход 8, батарея даёт максимум 150. Конденсатор уменьшает время
  накопления полного выстрела с 40 до 30 тиков. До полного накопления выстрел слабее.
- **Дуплет:** базовая вместимость 2; `metro_duplet_extra_barrels` даёт 4. Используется один ID
  оружия и динамический запрос вместимости по стеку, без изменения общей `GunType`.
  Один выстрел расходует один патрон. Залпы 2/4 и перепривязка ПКМ не добавляются.
- Обвесы Дуплета меняются атомарно **в том числе на заряженном оружии**, вне перезарядки.
  Установка +2 стволов сохраняет заряд. При снятии остаётся до двух патронов, избыток возвращается
  в инвентарь настоящим заряженным типом (`bullet` NBT) с сохранением его метаданных.
  Если не помещаются обвес/патроны или данные боеприпаса некорректны, вся операция отменяется
  без расхода нового обвеса и без изменения оружия. Во время reload/unload смена заблокирована.

Правила давления/энергии — явная игровая адаптация, не обещание идентичных оригиналу формул.

### Enhanced-сеть

В выбранной базе `PacketExpShot` расходует патрон и воспроизводит звук, а отдельные
`PacketExpGunFire` обрабатывают попадания. Поэтому патч проверяет **логический выстрел**
перед родным расходом, затем разрешает попадания только для этого стека и короткого окна
выстрела. Давление расходуется один раз, а не на каждую дробину. Повторные попадания по одной
цели ограничены количеством дробин. Множитель давления применяется к урону и бонусу в голову.
Для этих Enhanced-стволов также закрыт обход через старый пакет BASIC-выстрела.
Это дополнение к валидации исходного MWF, не новый полноценный серверный raycast/античит.

Динамическая вместимость заменяет 14 чтений `internalAmmoStorage`; ещё одно чтение при первоначальном автозаряжании заменено отдельным `initialAmmoCount` (0 только для Дуплета). Это применяется в загрузке/подтверждении
перезарядки, инициализации, HUD, Enhanced-рендере и ScriptAPI. Четыре чтения BASIC-анимаций
не меняются: механики выстрела этой поставки рассчитаны на Enhanced-оружие нашего пака.

## Звук

Существующие обычные выстрелы не меняются. Для совместимых глушителей создаются отдельные
OGG на основе записей пака: фильтрация, компрессия, короткий хвост и меньшая дальность.
Это **не оригинальные записи Metro с глушителем**. Штатный `isSuppressor` выбирает отдельное
событие в клиентском и серверном звуковых путях. Для накачки добавляются короткие аудиосигналы.
Дульный тормоз Абзаца и пламегаситель Вентиля/Преведа исправлены: не классифицируются как звуковые глушители.

## Проверки и ограничения

- JDK 17 компилирует runtime-код в Java 8; входные SHA проверяются.
- Изолированные JVM-тесты с явными фасадами Minecraft проверяют правила, разрешение
  выстрелов/попаданий, накачку, расход, утечку, батарею/конденсатор, независимую вместимость,
  возврат модулей, заполненный инвентарь, NBT и блокировки перезарядки.
- ASM проверяет счётчики вставок и корректность стеков изменённых методов через BasicVerifier.
- Ни один compile/test facade `net.*`, `io.*`, `com.*` не включается в результат.
- OBJ, glTF, UV, PNG, позы, руки и анимации сохраняются. Новая анимация насоса не придумана.
- Огнемёт, вращение Gatling, автоадаптеры, полноценные ПНВ/кратность оптики пока не реализованы.
- **Minecraft/Forge/OpenGL и реальная сетевая игра здесь не запускались.**

Сборка:

```sh
python -m pip install imageio-ffmpeg==0.6.0
python tools/build_mwf_mechanics.py --mwf-jar /path/to/selected.jar
```

Выход: изменённый MWF JAR, полный контент-пак v4, русская инструкция и JSON-отчёт с SHA/проверками.
Установить новый JAR вместо старого и v4 ZIP вместо предыдущего пака, одинаково на обеих сторонах.

## Исправление приложенного краша (metro2)

Отчёт `crash-2026-11-04_18.17.44-client.txt`: `ArrayIndexOutOfBoundsException: 1`
в `GuiGunModify.lambda$null$12`, строка 1457. В точном базовом JAR это
`AttachmentType.modelSkins[skinId]`: сохранённый индекс 1 при единственной текстуре.

ASM заменяет прямые чтения `modelSkins[index]` в классах MWF на типизированный
`SafeSkins.select`. Валидные индексы сохраняются; отрицательный/слишком большой индекс
получает первую непустую запись. Нулевой/пустой массив показывает missing texture, а не
роняет GUI. NBT на клиенте не переписывается. Две выборки в точном месте краша
проверяются счётчиком `crashGuiSkin=2`; изменённые методы проверяет ASM BasicVerifier.

Новые выходы: `modularwarfare-shining-2024.2.4.6f-fix1-metro2.jar`,
`Metro_Full_Arsenal_MWF_fix1_v4_mechanics.zip`, `MWF_Mechanics_v2_report.json`.
Оба файла ставить вместе вместо metro1/v3. Прежние бинарники не перезаписываются.
Исходные формулы накачки и отдельные обработанные звуки глушителей сохранены.
Тесты дополнены сменой заряженных обвесов, возвратом 0/1/2 патронов с NBT,
заменой на глушитель/удлинитель, unload-all, полным инвентарём, слиянием патронов,
rollback при ошибке записи, отсутствующим/неверным типом боеприпаса и ошибочными skinId.
Minecraft/Forge/OpenGL и реальная сеть по-прежнему не запускались.

## Исправления metro3 / пак v5

Повторный отчёт пользователя: вылет при накачке, новый Дуплет уже заряжен, патроны
не расходуются. Нового crash-report пока нет, поэтому точное соответствие нового
вылета найденной ошибке требует подтверждения в игре/логе.

* Найдена ошибка compile facade: `ByteBuf.readUnsignedByte()` был объявлен как `int`,
  но реальный Netty возвращает `short`. Получался вызов несуществующего `()I`.
  Пакет теперь читает настоящий `readByte()B` и преобразует в unsigned через `& 0xff`.
  Запись осталась однобайтовой; диапазон 0–8 проверяется сервером. ASM дополнительно
  проверяет ABI скомпилированного пакета перед публикацией.
* Тик накачки и HUD больше не выбрасывают новые IllegalStateException в клиентский
  цикл при ошибке. Причина пишется в latest.log; неисправный обработчик отключается
  до смены мира, для накачки появляется сообщение. Успех не симулируется.
* Подтверждено в исходном байткоде: `defaultBullet` автоматически заполнял
  `ammocount` до `internalAmmoStorage` при первом создании NBT. Для Дуплета это
  единственное место теперь пишет 0, НЕ изменяя вместимость 2/4 и перезарядку.
  Уже имеющиеся стеки не обнуляются: достоверно отличить вручную заряженные патроны
  от старого автозаряжания невозможно.
* `ItemGun.hasAmmoLoaded` для Дуплета возвращает false: это оружие с внутренним
  боезапасом, не съёмным магазином. Наличие старого `ammo` в NBT больше не переводит
  `getAmmoCount`/`consumeShot` на чужой магазин вместо `ammocount`. Сам старый тег
  не удаляется и предметы из него не создаются. Остальные пушки не меняются.

Предыдущие тестовые реализации `hasNextShot` заменены запуском четырёх **реальных
методов выбранного MWF JAR** (`hasAmmoLoaded`, `getAmmoCount`, `hasNextShot`,
`consumeShot`) в изолированной API-среде. ASM переносит их с production-хуками
в test-only backend перед JVM-тестом; без переноса заглушки бросают AssertionError.
Это не запуск Minecraft. Проверяются 2/4 заряда, 8 дробин на один расход,
отказ на третьем/пятом выстреле, старый magazine NBT, сохранность других пушек
и round-trip сетевого пакета накачки с реальными примитивными дескрипторами.

Выходы: `modularwarfare-shining-2024.2.4.6f-fix1-metro3.jar`,
`Metro_Full_Arsenal_MWF_fix1_v5_mechanics.zip`, `MWF_Mechanics_v3_report.json`.
Ставить оба файла вместо metro2/v4; одинаково на клиенте и сервере.
Новая модель/анимация гильз Дуплета не добавлялась: это исправление игрового
счётчика и расхода патронов, а не разделение слитой геометрии на отдельные гильзы.

## metro4 / пак v6 — жизненный цикл Enhanced-перезарядки

После metro3 пользователь подтвердил: Дуплет после зарядки стреляет больше двух
раз с уроном; накачка не увеличивает индикатор (он остаётся 0). Свежего лога
metro3 пока нет: имеющиеся в uploads latest.log/debug.log относятся к исходному
fix1 и старому паку Убойника, а не к новому запуску. Режим игры/сервер не уточнены.

В выбранном исходном JAR найден **воспроизводимый дефект нашей интеграции**:
`PacketGunReloadEnhancedStop.handleServerSide` вызывает обработчик loose/magazine
перезарядки и синхронизирует слот, но успешные ветки оставляют `reloadEnhancedTask`.
`ServerTickHandler` удаляет истёкший `playerReloadCooldown`, но не этот task.
Наш `busy()` ошибочно трактовал любую такую запись как ещё активную перезарядку.
Следствие: после первой зарядки сервер отклоняет логические выстрелы, возвращая
старый ammocount, и отклоняет накачку. Это объясняет застывший боезапас/давление,
но сообщение пользователя о продолжающемся уроне отдельно не воспроизведено
в Minecraft: игровой запуск и свежий лог всё ещё необходимы.

Исправление — захват scoped-task на входе нативного EnhancedStop и удаление
этого же экземпляра на всех **трёх нормальных выходах**, ПОСЛЕ нативного переноса
патронов/синхронизации. Задача новой перезарядки не удаляется старым callback.
Чужие пушки не затронуты. При исключении задача не снимается (fail-closed).
Cooldown не обнуляется, незавершённая перезарядка по-прежнему блокирует накачку,
выстрел и смену обвесов. Повторный stop больше не переиспользует завершённый task.
Клиентский gate также проверяет настоящий hasNextShot у scoped-оружия.

Тесты: остаточный task после simulated native commit воспроизводит отказ, затем
completion-hook снимает блокировку; две последовательные перезарядки одного
Дуплета для вместимостей 2/4, реальные нативные consumeShot/getAmmoCount, запрет
третьего/пятого выстрела; decoded pump после completed magazine reload для трёх
энерго-пушек увеличивает давление 0→20→40; активный cooldown остаётся; позднее
завершение не удаляет новую задачу; сторонняя задача сохраняется. Сам commit
перезарядки в этих тестах — явная fixture, не полный нативный/Minecraft reload.
ASM проверяет счётчики `reloadTask=1`, `finishReload=3`, кадры и стек.

Выходы: `modularwarfare-shining-2024.2.4.6f-fix1-metro4.jar`,
`Metro_Full_Arsenal_MWF_fix1_v6_mechanics.zip`, `MWF_Mechanics_v4_report.json`.
Реальный Minecraft/Forge/мультиплеер не запускались. Не называть это игровым тестом.
