# Ручной пулемёт: вращение и раскрутка; Подонок/револьвер: хват с прикладом

## Установка — нужны ДВА файла

1. Сохранить резервную копию мира и закрыть игру/сервер.
2. В `mods` **заменить** прежний MWF JAR (включая metro4) на
   `modularwarfare-shining-2024.2.4.6f-fix1-metro5.jar`.
   Не оставлять одновременно два MWF и старый duplet-bridge.
3. В `.minecraft/ModularWarfare/` **заменить** прежний Full Arsenal на
   `Metro_Full_Arsenal_MWF_fix1_v9_motion.zip`. Не устанавливать v8/v9 рядом.
4. У всех клиентов и на сервере должны быть одинаковые metro5 JAR и v9 ZIP.
   Версия сетевого мода намеренно изменена на `2024.2.4.6f-metro5`:
   клиент metro4 не должен входить на сервер metro5 и наоборот.
5. Для осмотра вне игры использовать **`MWF_Armory_Studio_v5.zip`**.
   В нём нет встроенных моделей или оружия: открыть свой v9 ZIP.

Это не полная сборка/лаунчер Minecraft. Нового отдельного bridge-мода нет:
изменения интегрированы в ту же предоставленную пользователем закрытую MWF.
Переход с v8 не удаляет дополнительные предметы. При переходе с v7 и старше
сначала выполнить миграцию старых обвесов Убойника из `MWF_3D_V8.md`.

## 1. Вращение и разгон ручного пулемёта

- Удерживание **назначенной в Minecraft кнопки выстрела**, не жёстко заданной ЛКМ,
  запускает плавную раскрутку. Отпускание плавно замедляет блок стволов.
- Вращаются отдельные исходные меши **обычного и пятиствольного блока**.
  Корпус, магазин и руки не вращаются вместе со стволами.
- Ось взята из `Render_Gatling.java`: `glRotatef(stvolrot,0,0,1)` в исходной
  системе координат. Экспортёр повернул модель `Ry(90)`, поэтому в glTF это ось X.
  Поворот происходит вокруг исходного центра, а не центра габаритного параллелепипеда.
- Разгон до полной скорости: **20 тиков / 1 сек**, с мотором — **10 тиков / 0,5 сек**.
  Остановка с полной скорости: **30 тиков / 1,5 сек**. Время дано для 20 TPS.
- Первый выстрел разрешается только после начала раскрутки: порог сервера 25%.
  Клиент использует 30% для предсказания (примерно 0,3 сек без мотора / 0,15 сек с ним).
- Темп нарастает вместе со скоростью. Полный темп — **400 выстр./мин** у обычного
  блока, **600 выстр./мин** у пятиствольного. Сервер округляет интервалы вверх до тика;
  клиент использует те же интервалы, а не изменяет общий `GunType` для всех игроков.
- Значения 400/600 соответствуют верхним исходным интервалам 3/2 тика из donor Gatling.
  **Кривая разгона и торможения — явная адаптация MWF**, не доказанное воспроизведение
  всех таймингов Metro. Полная угловая скорость — 1200°/сек.
- Перезарядка, спринт, смерть, пустой боезапас, потеря фокуса и открытое меню прерывают
  нажатие. Смена оружия/слота/мира сбрасывает серверное состояние раскрутки.
- Проверка на сервере: холодные/слишком частые выстрелы отклоняются **до родного
  списания патрона**. Legacy/basic-пакет не обходит разгон. Hit-пакет не может
  сам создать разрешение на выстрел; повторное попадание в одну цель отклоняется.
- Клиент отправляет только состояние кнопки и слот. Скорость и разрешение выстрела
  клиент не назначает. Положительное нажатие истекает без обновления через 10 тиков.
- Для наблюдающих игроков сервер передаёт образцы угла/скорости раз в 4 тика через
  штатный `sendToAllTracking`, не всем игрокам во всех измерениях.

Оригинальная пневматика/ручное взведение механизма/новая петля звука вращения
в эту версию не добавлены. Струя огнемёта также не относится к этой правке.

## 2. Разные руки с прикладом и без

- Подонок: `metro_mod_podonok_butt` в слоте `stock` автоматически включает свой хват.
- Револьвер: `metro_mod_butt` в слоте `stock` автоматически включает другой хват.
- Для каждого оружия отдельно изменяются обе руки. Classic/Steve и slim/Alex
  используют одинаковые дельты через общий родительский узел соответствующей руки.
- Без приклада остаются **точно прежние узлы рук, исходные анимационные ключи и позы**.
  В частности, ранее замороженный хват револьвера без приклада не перенастроен.
- После снятия приклада возвращается исходная поза, без накопления смещений между кадрами.
- Новые хват/опорная рука заданы в сохранённой системе координат MWF. Поворот предплечья
  задан вокруг существующей точки кисти, а не вокруг начала узла, чтобы кисть не
  вылетала поверх ствола. Это авторская адаптация, не импорт несовместимой камеры donor.
- Дельты накладываются на текущую анимационную позу: ADS, обычное держание и существующую
  перезарядку. Новая последовательность перезарядки не выдумывалась.
- Добавлены только родительские motion-узлы: исходные меши, UV и буферы анимаций
  Подонка/револьвера не переписываются. Барабан револьвера сохранён.

## Предпросмотр

Armory v5 автоматически меняет хват при включении соответствующего приклада
в разделе «Обвесы» / «Показать этот обвес в 3D».
Для ручного пулемёта справа есть кнопка **«Удерживай: раскрутка пулемёта»**.
Она работает указателем или удерживанием Space/Enter и показывает скорость/темп.
Мотор и пятиствольный блок в предпросмотре учитываются.

Общая реализация предпросмотра подключена и к исходникам standalone Pose editor.
Новый ZIP старого Pose v1 со встроенным оружием не выпускается — использовать
пустой Armory v5. Просмотр не запускает серверные проверки или реальный Minecraft.

## Проверки

- **385** прежних Java-проверок механик + **1055** новых проверок правил/хуков/кодека
  на явно отделённых API-фасадах. Потребление патронов проверялось настоящими четырьмя
  методами `ItemGun`, перенесёнными из выходного MWF JAR, не их ручной имитацией.
- Проверка стека ASM всех изменённых методов и точного числа вставленных хуков.
  Затронуты семь исходных классов; прежние классы `ru.metrocraft.mwf` сохранены побайтно.
- **6 Python-регрессий** на настоящих входном/выходном JAR и ZIP: сохранность ресурсов,
  покадровых буферов, старых матриц без приклада, оси/центра и двух вариантов стволов,
  согласованность профилей JAR/пака, версия байткода 52 и отсутствие тестовых фасадов.
- **66/66 Armory** и **22/22 Pose editor** Node-теста.
- Offline Chromium открыл реальный v9 ZIP с 25 оружиями. Проверено изменение матриц
  обеих рук Подонка/револьвера при установке приклада и **точное восстановление** при снятии,
  рендер ADS/slim/reload, изменение матрицы вращающихся стволов, разгон/замедление до нуля,
  пятиствольный блок с мотором и показ 600 RPM. Нет ошибок JS и HTTP-запросов.
  Скриншоты осмотрены; слишком высокое положение кисти в первоначальном варианте исправлено.
- Повторная сборка JAR и ZIP проверяется побайтным сравнением.

**Minecraft, Forge, OpenGL и настоящая сетевая игра здесь не запускались.**
Хват, посадку рук при перезарядке, OptiFine/шейдеры и ощущения от раскрутки ещё нужно
проверить в игре. Изолированные проверки и браузерный рендер этого не доказывают.
Helpers имеют Java 8 classfile 52, но запуск именно на Java 8 не выполнялся.
Текущая проверочная сборка использовала javac 25 `-source 8 -target 8` в ограниченном
окружении без ct.sym; это не проверка API Java 8. Обычная команда сборки с полным JDK
по умолчанию использует `--release 8`.

## Сборка из исходников

Основной инструмент: `tools/build_mwf_motion.py`; отдельные runtime-исходники
`tools/mwf-motion/src`. Старый v4 builder и его источники не подменены.

Нужны полный JDK 17+, NumPy и build-only ASM core/tree/analysis (один ASM-all JAR
или classpath трёх JAR). ASM и API-фасады в игровой JAR **не включаются**.

```sh
python tools/build_mwf_motion.py \
  --jar downloads/modularwarfare-shining-2024.2.4.6f-fix1-metro4.jar \
  --pack downloads/Metro_Full_Arsenal_MWF_fix1_v8_3d.zip \
  --asm /path/to/asm-all.jar
python -m unittest discover -s tests -p test_mwf_motion.py -v
npm ci --prefix tools/mwf-armory
npm test --prefix tools/mwf-armory
npm run build --prefix tools/mwf-armory
PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs \
MWF_CHROMIUM=/path/to/chromium node tools/mwf-armory/motion-smoke.mjs
```

Проверяются точные SHA-256 входного metro4 JAR и v8 ZIP. Патчер не принимает
произвольный upstream и не пересобирает оружие из старого pre-mechanics-пака.
Дополнительный `--java8-mode source-target` нужен только окружению без ct.sym;
использовать `--release 8` по умолчанию при наличии полного JDK.
