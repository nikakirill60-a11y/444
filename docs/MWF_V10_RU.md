# MWF v10 / metro6 — иконки, Велопал, хват Ашота, радиатор

## Скачать и установить

Нужны **оба** новых файла, одинаковые на сервере и у клиентов:

- [MWF fix1-metro6 JAR](../downloads/modularwarfare-shining-2024.2.4.6f-fix1-metro6.jar) — заменить старый MWF в `mods`.
- [Full Arsenal v10 ZIP](../downloads/Metro_Full_Arsenal_MWF_fix1_v10_icons.zip) — заменить старый оружейный пак в `.minecraft/ModularWarfare/`.

Не оставлять предыдущие MWF/Full Arsenal рядом с новыми. Перед обновлением
закрыть игру/сервер и сделать резервную копию мира. Старый duplet-bridge не нужен.
Версия сети изменена на `2024.2.4.6f-metro6`, чтобы не смешивать несовместимые версии.
Это не полная сборка Minecraft и не самостоятельный лаунчер.

Для просмотра подходит прежний пустой **Armory v5**: открыть в нём v10 ZIP.
Новая версия редактора не требуется и отдельный ZIP редактора не переиздаётся.

## 1. Все 25 иконок оружия

Перерисованы **все 25 инвентарных иконок оружия**. Иконки патронов/магазинов/старых
обвесов не входят в запрос «всё оружие» и не заменялись. Новый радиатор получил
собственную иконку.

Прозрачные PNG 256×256 получены офлайн-рендером настоящих текстурированных
мешей из итогового пака: без рук, вспышки и неустановленных обвесов. Отдельные
совместимые магазины добавлены в их исходных креплениях. Это не AI-изображения
и не посторонние похожие картинки; у каждого оружия свой новый PNG.
Рендер увеличенного разрешения уменьшен с антиалиасингом. Инвентарные ID сохранены.

## 2. Велопал: текстура из RAR и шесть зарядов

- Правильная текстура — **`wpn34_bigun.png` из пользовательского `3d.rar`**.
  В v8 её ошибочно применили к Убойнику. Теперь она назначена Велопалу,
  а Убойнику возвращена его собственная текстура из v7, вместе с его половиной гильз.
- PNG Велопала включён **побайтно**, без уменьшения в старую 64×64 ячейку атласа.
- Для тела Велопала UV переведены из общей ячейки атласа в исходный диапазон 0…1.
  Геометрия, индексы треугольников, нормали, старые анимационные буферы и руки не менялись.
- **Шесть дробовых патронов** во внутреннем боезапасе вместо пятизарядного
  винтовочного магазина `metro_vyhlop_ammo`. Боеприпас — существующая дробь 12 калибра.
- Десять дробин за выстрел сохранены. Один выстрел расходует один патрон, не десять.
- Отдельный магазин Выхлопа больше не принимается/не отображается Велопалом.
- Исходная модель статична: новая анимация барабана/поочерёдного заряжания не выдумана.

**Миграция:** до обновления разгрузить старые Велопалы на старой версии, чтобы вернуть
винтовочные магазины и патроны. Новый конфиг не переписывает старые NBT-стэки
и не превращает пять винтовочных патронов в шесть дробовых. Если старый экземпляр
сохранил несовместимый NBT, после возврата боеприпасов заменить его новым предметом.
Магазин Выхлопа не удалён из пака: остальные использующие его предметы сохранены.

## 3. Ашот с прикладом и без

При установке **`metro_mod_ashot_butt`** автоматически включается отдельный хват
обеих рук. Classic/Steve и slim/Alex поддержаны. Без приклада остаются точные
прежние позы; снятие возвращает их без накопления смещений.

Подход тот же, что у револьвера и Подонка: два дополнительных родительских узла
с матрицами хвата, без замены исходных узлов рук/ключей анимации/мешей. Поворот
предплечья задан вокруг существующей кисти. Дельты накладываются на действующую
позу, в том числе ADS и перезарядку; это не новая последовательность перезарядки.
Хват револьвера, Подонка и раскрутка ручного пулемёта сохранены.

## 4. Радиатор Ублюдка — обвес

Причина постоянного радиатора в v8/v9: меш был добавлен в glTF без условия
видимости и не попал в `defaultHidePart`.

Теперь **`metro_mod_ubludok_radiator`** — отдельный предмет «Радиатор для Ублюдка»
в слоте **barrel**. По умолчанию снят; установка показывает существующий
`ubludokRadiatorModel`, снятие скрывает его. Сам меш, текстура и посадка не переделаны.
Слот общий с глушителем, поэтому глушитель и радиатор не устанавливаются одновременно.
Стандартное оружие при обновлении потеряет только ошибочно постоянную видимость
радиатора: сам предмет надо взять отдельно. Автоматическая выдача/дюп обвеса не добавлены.

У радиатора нет выдуманного усиления урона, охлаждения или системы перегрева.
Он не объявляется глушителем и не скрывает вспышку.

## 5. Медведь

Почему он стрелял дробью: в первом переносе унаследовал настройки Убойника —
12 калибр, восемь дробин за выстрел и шестизарядное внутреннее хранилище.
После уточняющего вопроса пользователь **прямо подтвердил «дробь»**.
Поэтому в v10 Медведь **оставлен дробовиком**: конфиг оружия, модель, текстура
и рендер не переделаны. Изменена только запрошенная общая новая иконка.
Пневматическая механика или произвольно выбранный винтовочный калибр не добавлены.

- **385** существующих изолированных Java-проверок механик.
- **1055** существующих изолированных проверок раскрутки/пакетов/хуков.
- **241** новая Java-проверка реального клиентского хука Ашота с матрицами
  из выходного пака: правильный/неправильный приклад и слот, обе руки,
  восстановление позы и отсутствие накопления/утечки контекста. Также проверены
  шесть расходов патронов и отказ седьмого выстрела настоящими методами `ItemGun`,
  перенесёнными из итогового JAR в тестовый фасад.
- **7 Python-регрессий** на настоящем ZIP/JAR: все новые иконки, точная текстура
  из RAR, UV, ёмкость/тип патрона Велопала, неизменный Медведь, опциональный радиатор,
  старые матрицы/анимации Ашота, профили пака/JAR и строгий список изменённых ресурсов.
- **3 Node-теста** общего motion-предпросмотра.
- Offline Chromium открыл **все 25 оружий** из v10 в пустом Armory v5.
  Для Ашота/Подонка/револьвера проверены изменения матриц обеих рук от приклада
  и точное восстановление после снятия, рендер ADS/slim/reload. Проверены
  шесть выстрелов счётчика Велопала и отказ седьмого, новая текстура, радиатор
  выключен/включён и исключение одновременного глушителя, сохранённая дробь Медведя,
  вращение/разгон/остановка Gatling. Нет ошибок JS и HTTP-запросов.
  Скриншоты Ашота, Велопала и радиатора осмотрены. Это не Minecraft.
- Повторная сборка в другой выходной папке дала **побайтно идентичные JAR и ZIP**.

В runtime заменены только основной `MotionClient.class`, версия в
`ModularWarfare.class` и JSON motion-профилей. Все остальные runtime-классы,
включая серверную стрельбу/перезарядку/сеть, сохранены побайтно. Тестовые фасады,
ASM и компилятор в игровой JAR не включены. Классы helper — Java 8 / classfile 52.

**Minecraft/Forge/OpenGL и реальная сетевая игра здесь не запускались.**
Автотесты на фасадах и браузерный рендер не доказывают правильную посадку рук
при всех игровых анимациях. Реальный Java 8 не запускался: локально использован
javac 25 source/target 8 в окружении без ct.sym. С полным JDK builder по умолчанию
использует `--release 8`.

## Воспроизведение

Инструмент `tools/update_mwf_v10.py` принимает только точные SHA входных
v9 ZIP / metro5 JAR / v7 ZIP. Старые builders v8/v9 и их runtime-исходники не изменены.
Исходник нового клиента отдельно: `tools/mwf-v10/src/ru/metrocraft/mwf/MotionClient.java`.

```sh
python tools/update_mwf_v10.py --pack /path/to/v9.zip --jar /path/to/metro5.jar \
  --v7 /path/to/v7.zip --asm /path/to/asm-all.jar
MWF_V9=/path/to/v9.zip MWF_V7=/path/to/v7.zip MWF_METRO5=/path/to/metro5.jar \
  python -m unittest discover -s tests -p test_mwf_v10.py -v
npm ci --prefix tools/mwf-armory
npm run build --prefix tools/mwf-armory
PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs MWF_CHROMIUM=/path/to/chromium \
  node tools/mwf-armory/v10-smoke.mjs
```

Нужны NumPy, Pillow, полный JDK 17+ и build-only ASM core/tree/analysis.
Для ограниченного окружения без ct.sym есть явный `--java8-mode source-target`;
это не проверка совместимости API Java 8.
