# Полная сборка из GitHub Releases

Лаунчер автоматически читает стабильные опубликованные релизы репозитория
`nikakirill60-a11y/444` (последние 100; самый новый `published_at` с нужными assets).
Draft и prerelease игнорируются. Релизы только с JAR или EXE не считаются сборкой.
Полный модпак пока не предоставлен и в Releases не опубликован.

## Подготовка автором, не пользователем

1. Собрать полный ZIP игровых данных, включая mods, MWF/packv4, config и ресурсы.
   Не включать пароли, accounts.json, токены, чужие миры, приватные адреса и скрипты.
   Сохранить как **MinETRO-Modpack.zip**. В корне обычно папка `mods/`.
2. Выбрать неизменяемый тег, например `pack-v1`. Подготовить контрольный файл:

   ```sh
   python launcher/create_channel.py MinETRO-Modpack.zip \
     --url https://github.com/nikakirill60-a11y/444/releases/download/pack-v1/MinETRO-Modpack.zip \
     --version pack-v1 --out MinETRO-Modpack.json
   ```

   Историческое имя скрипта осталось для совместимости, но ручных каналов в UI нет.
   Если игровые данные лежат внутри папки ZIP, добавить `--root ПАПКА`.
   JSON — внутренние SHA256/размер/список модов для проверки загрузки. Это не
   дополнительная настройка пользователя и не отдельный источник модпака.
3. Опубликовать оба файла в одном обычном (не draft/prerelease) GitHub Release:

   ```sh
   gh release create pack-v1 MinETRO-Modpack.zip MinETRO-Modpack.json \
     --repo nikakirill60-a11y/444 --title 'MinETRO pack-v1' --notes 'Полная сборка MinETRO'
   ```

   Эта команда выполняется только после фактической сборки/проверки полного архива.
   Пустой релиз или один JAR ради имитации готовности создавать нельзя.
4. Не перезаписывать файлы опубликованного релиза. Изменения — новым тегом/версией.
   На Windows проверить фактическую установку и Minecraft/MWF/руки перед выдачей.

Лаунчер проверяет, что обе ссылки ведут на assets этого же репозитория и тега,
размер ZIP совпадает с GitHub, а SHA256 — также с asset digest GitHub, если он есть.
После скачивания всегда проверяются SHA256, безопасная распаковка и моды.
SHA256 не гарантирует безвредность Java-кода: репозиторий должен оставаться доверенным.

После входа выполняется автоматическая проверка, также есть кнопка «Проверить
обновления» в настройках. При сетевой ошибке уже сохранённый релиз не стирается.
Старые пользовательские `active-channel.json` не читаются: используется отдельный
локальный cache `github-release` в каталоге настроек.

Регистрация ограничивает доступ к интерфейсу и действиям штатного лаунчера. Файлы
публичного GitHub Release сами по себе не защищены аккаунтом MinETRO: их можно скачать
прямой ссылкой. Это не DRM и не серверная защита платных/приватных файлов.
