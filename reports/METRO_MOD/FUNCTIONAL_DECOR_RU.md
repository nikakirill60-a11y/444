### Один дополнительный сборщик материалов И текстур

`downloads/finishdecor.py` принимает локальную папку content, проверяет SHA256
Models.jar, выбирает 187 уже подтверждённых материалов и недостающие модельные
детали. Для дополнительных моделей читает только заголовок, чтобы получить
настоящий mtllib. Материалы расшифровывает встроенной AES-128 реализацией без pip,
PowerShell, сети, запуска Java или сторонних команд. Затем читает map_Kd и собирает
связанные diffuse/normal/specular/emission из `Metro2033TexturesN.jar`.

```bat
py -3 "%USERPROFILE%\Downloads\finishdecor.py" "D:\New Folder\Minecraft Metro 2033 Client\content"
```

Выход: новая папка `content/metro_decor_finish_parts`, части `metro_decor_finish_*.zip`
не более 90 MiB и `decor_finish_inventory.json`. Нужны все эти выходные файлы.
По умолчанию выбирается максимальная доступная текстура не выше 512; если такой
нет — минимальная выше 512, это явно помечается в отчёте. Размер можно поменять
через `--size 256|512|1024|2048|4096` (также поддерживается 128).

Это **исходные ресурсы, не мод для установки**. Неизвестные map_Kd options,
проблемы padding/материалов, отсутствующие модели/материалы/diffuse перечисляются,
не скрываются под «готово». Нормали/блики/свечение собираются для сохранения
исходников, но не объявляются работающим GLSL-рендером в 1.12.2.

Сам сборщик на недоступных больших локальных архивах здесь не запускался.
Проверки: FIPS-197 AES128 known-answer, сравнение с PyCryptodome на разных длинах,
сравнение начала всех 187 реальных OBJ, синтетический полный проход model header →
material → texture → ZIP/CRC/SHA256. Это не проверка интерфейса Windows или игры.

Остальная часть документа ниже описывает первоначальный аудит **до получения ZIP**.
Утверждение о недоступной геометрии там историческое; текущий блокер — материалы,
текстуры и оставшиеся детали, затем сам перенос поведения/рендера и игровая проверка.

## Что мешает завершить перенос

Оригинальная геометрия `.m2033model` находится в `Metro2033Models.jar` (616729038 байт).
Коннектор скачивает максимум 104857600 байт на файл. Модели/UV/подвижные детали
и внутренние зависимости из этого архива пока не получены. Большой файл повторно
не запрашивался; предполагать, что ссылки равны готовым моделям, нельзя.

Поиск Drive по germo/Germo/lever/m2033model не нашёл отдельно выложенных
`.m2033model`. Найденные OBJ/PNG/Forge-классы других наборов не подставляются
вместо оригинала. Это ограничение доступа к данным, не проблема сборки Java.

Ниже перечисление каталога — **не список уже добавленных в игру предметов**.
Inventory пока обозначает лишь тип профиля: реальные слоты/размеры, содержимое,
антидюп и серверный обработчик не восстановлены. Light не гарантирует включение
по рычагу или полноценный динамический свет. Для Germo/Lever/Door ещё требуется
проверить формат состояний и связи управления, не выдумывать redstone как поведение донора.

## Подготовленные инструменты

- `tools/audit_metromod_decor.py`: воспроизводимый статический разбор с проверкой
  SHA256 до чтения байткода. Донорская Java не исполняется. Реализации функций
  не копируются в мод автоматически. Все записи имеют `runtime_ported: false`.
- `reports/METRO_MOD/functional_decor_audit.json`: тип, имя, модель, смещение
  регистрации, классы обработчиков и прямые зависимости каждой записи.
- `downloads/collect_metromod_decor.py`: самостоятельный Python 3 без зависимостей,
  извлекает только нужные 192 модели/детали из **локального** архива.
  Новая папка `metro_decor_parts`, ZIP-части <=90 MiB, SHA256 каждого файла/части,
  отсутствующие пути перечисляются. Никакой полной распаковки или исполнения классов.
  Путь traversal/симлинк/неоднозначные совпадения/слишком большой одиночный файл
  отвергаются, прежний результат не перезаписывается. Исходные зашифрованные байты
  сохраняются без изменения. Это сборщик исходников, НЕ устанавливаемый мод.

```bat
py -3 collect_metromod_decor.py "C:\Metro\content\Metro2033Models.jar"
```

На настоящем Models.jar утилита **не запускалась**: доступных байтов нет.
После получения модельных частей ещё нужно декодировать формат и собрать ссылки
на реальные текстуры/материалы внутри моделей; 192 — уточнённые прямые зависимости кода,
не доказательство полного транзитивного набора.
