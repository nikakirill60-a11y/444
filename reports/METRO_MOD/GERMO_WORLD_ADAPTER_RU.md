# Germo: подключение исходных callback к игровому миру

## Изменения исходников

Для всех **17 Germo** `OriginalGateTile` теперь использует `DonorGermoMotion`,
а не воксели движущегося меша. Расчёт выполняется на сервере с `delta40=2`
(20 тиков/сек). Оригинальные пороги, флаги сегментов, предыдущие векторы и порядок
операций сохранены. 27 Door сохраняют отдельный ранее перенесённый AABB-контракт.
Lever/Light этим этапом не изменены.

* Кандидат следующего состояния рассчитывается на копии. При чужом блоке,
  UUID, выгруженном чанке, живой сущности или отказе установки/снятия proxy
  новый snapshot не принимается. При отказе снятия восстанавливаются уже
  снятые собственные proxy; чужие блоки не присваиваются и не удаляются.
* Физика берётся из сохранённого множества донорских клеток. `Progress` остаётся
  только косметическим значением: его изменение само по себе не открывает ворота.
* `DonorGermo` NBT Version 1 хранит animation XYZ, previous XYZ, флаги сегментов
  и integer-клетки. Те же поля идут в штатных tile packets. Клиент не предсказывает
  изменение физических клеток. Размеры/тип/числа snapshots ограничены.
* LayoutVersion 4 мигрирует прежние принадлежащие контроллеру proxy. Чужой UUID
  останавливает миграцию без уничтожения контроллера. Старое положение без
  snapshot воспроизводится проходом исходных callback, а не вокселизацией модели.
* При установке нового предмета закрытое состояние получается воспроизведением
  донорского закрытия в пустую локальную сетку. Это **адаптация нового предмета**,
  а не восстановление исходного состояния оригинальной серверной карты.

## Координаты: подтверждённый путь

Статически проверены `iIllIijlIIiijIiIjIliiIlIilIjjlij` и synthetic `$1`:
для block-mode enum выбирается `ilijlljlIIjjIIlIIjjIiIiilijIIIil`.
Его transform: `T(state) R(y,x,z) T(catalogue offset) S(catalogue scale * instance scale)`.
**Не добавлять .5 от другого renderer:** у этого пути его нет.

Сначала donor callback сам поворачивает координаты и вызывает `Math.round`.
Уже полученный integer-куб обратным преобразованием переводится в unit-scale
координаты модели, затем применяются текущие ground/offset/facing MinETRO.
Каталожные смещения/масштабы взяты из `client.jar`, а не из min/max меша.
Runtime-метаданные: `metromod_germo_collision.json`; источник и class-хеши —
`DONOR_GERMO_BLOCK_RULES.json`. Индивидуальные map-only translation/scale не известны;
используется явно оговорённый canonical translation 0 / instanceScale 1.

## Проверки

Локально, отдельно от Forge:

* исходные **2448** bytecode differential fixtures / **4904** assertions PASS;
* motion/развороты/copy-on-tick/snapshot/affine round-trip:
  **17 профилей × 4 yaw**, **268484 assertions PASS**;
* ECJ, target Java 8, JRE17. Это компиляция чистого ядра, не всего Forge-мода.

Добавлен `DonorGermoCollisionTest` (9 тестов): World-адаптер, координаты,
сохранение/сеть/разворот, камень в проёме, отказ снятия proxy, чужой UUID,
повреждённый snapshot. Прежние mesh-sweep ожидания Germo заменены проверкой
донорских клеток/таймингов; tests Door/Lever/Light не ослаблялись.

**Полная Forge-компиляция/JUnit и gameplay пока не подтверждены. Нового JAR
на момент записи нет.** Ранее сборка останавливалась при разрешении зависимостей.

## Попытка полной сборки

CI `43931403147`: **309 Python PASS**, Java8 standalone PASS, затем остановка
при конфигурации `:_compileJava_1`: `MinecraftRepo` вернул `client.jar` вместо
POM. В этой попытке ошибки legacydev уже нет. Компиляция runtime/JUnit не началась.

Добавлен ограниченный CI workaround: зависимости `net.minecraft:client:<MC_VERSION>`
переводятся на **уже выбранный данным Forge `MCP_VERSION`**. Именно эта версия
нужна `MCPRepo.findPom`; новый Minecraft/Forge/MCP не выбирается, транзитивные
зависимости не отключаются, фиктивный POM не создаётся. Требуется новая CI-проверка.

Ограничение визуальной части: TESR пока использует прежнюю scalar progress →
preview-matrix интерполяцию. Для многоосевых последовательных створок это не
доказывает точное покадровое совпадение картинки с донорской animation XYZ.
Перенос исходных физических callback не следует выдавать за проверенный gameplay.
