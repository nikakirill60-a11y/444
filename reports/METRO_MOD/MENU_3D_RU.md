# Оригинальное 3D главное меню METRO_MOD → 1.12.2

## Статус — dev32, runtime TEST

**Экран исходной 3D-сцены теперь подключён** через client-only GuiOpenEvent
к ванильному GuiMainMenu при отсутствии мира. Это первый runtime-тест,
**не подтверждённая точная копия**: Minecraft здесь не запускался.
Встроены надписи панели, fixed-function свет/туман, капли/glow и исходный звук.
Руки, MWF, packv4 и игровой renderer не изменяются.

Полная инструкция и ограничения: `docs/METRO_MENU_DEV32_RU.txt`.
Возврат к обычному меню: F8 или JVM-флаг `-Dmetroport.disableOriginalMenu=true`.
Инициализация/рисование при Java-ошибке возвращают обычное меню без повторного hook.
Вход — только по активации переключателя и только `localhost:25565`.
Старые сайт/авторизация/скины/статус не активируются.

**Оставшиеся отличия:** шрифт от 1.12.2, штатный GuiOptions вместо донорской
3D-панели настроек, тело игрока и тряска ещё отсутствуют; MTL/шейдерные каналы
не сверены с донорским рендером. Нужна реальная проверка света/прозрачности/UV
и сравнение кадров. Сайт не настроен, онлайн не выдумывается.

## Подключение и lifecycle

- `OriginalMenuScreen`: перспектива 70°, .1..100; исходный порядок camera/scene.
  Все 35 meshes загружаются до начала интро. Мышь/клавиатура/колесо/Enter/Space;
  Esc отпускает курсор, клик захватывает без активации. Потеря фокуса отпускает
  мышь и приостанавливает кадр; звук экрана останавливается на потере фокуса.
- `OriginalMenuClient`: только ClientProxy; не затрагивает pause/inventory/world
  и сторонние подклассы GuiMainMenu. При выходе, настройках, ошибке и resource
  reload освобождаются только принадлежащие меню display lists и sound handles.
- `MenuGlScope`: projection/modelview/viewport/driver attributes, shader,
  активная texture unit, binding, clear/current color и GlStateManager caches
  восстанавливаются. На этом этапе это проверка кода, не аппаратный GL-тест.
- Эффекты получены из SHA-проверенного исходного Content.jar:
  `menu_effects_verified.json`, 2 decoded PNG и исходный quad.obj. Не выдуманы.
- `OriginalMenuAudio`: 6 зарегистрированных событий, 21 исходный OGG; громкости
  донора .3/.4/.7/1/.5/.25, без пространственного затухания. Повтор не дублирует
  играющий handle; close не вызывает глобальный stopSounds.

## Геометрический каркас исходной сцены

- `client/menu/OriginalMenuGeometry.java`: 35 исходных model reference, точный
  порядок translate/rotate/scale для Regina, четырёх колёс, панели, стрелки,
  четырёх переключателей, вентиляторов, интро-гермоворот, труб, корней/паутины
  и пяти вариантов тоннеля. Генерируется из SHA-проверенного CFR-референса
  `tools/generate_metromod_menu_scene.py`, не из придуманных координат.
  Генератор допускает только mesh/transform/control-flow statements; текст,
  сеть, чужая авторизация и рендер тела игрока сознательно не извлекаются.
- `OriginalMenuState.java`: стартовые параметры, исходные эксклюзивные области
  четырёх кнопок и их приоритет, ограничение мыши, разгон, открывание ворот,
  цикл тоннелей/декора и движение переключателей/стрелки. `tick()` и `advance()`
  раздельны, как updateScreen/drawScreen донора. Не является всем GUI-state:
  автодоводка камеры, экран настроек, shake/audio lifecycle ещё отсутствуют.
- `OriginalMenuScene.java`: порядок композиции камеры/Regina/движущейся сцены;
  draw не меняет время или координаты. Это **mesh-only**: текст, тело игрока,
  частицы/glow и надписи подключены через отдельные callbacks. Все matrix push разворачиваются в finally,
  в том числе при ошибке загрузки модели.
- `OriginalMenuMeshes.java`: адаптер Forge 1.12.2 с отдельной diffuse-текстурой
  на каждый usemtl и ленивыми display lists. Неполный manifest/материалы дают
  явную ошибку, не подставной атлас. `close()` освобождает списки. Этот класс
  создаётся экраном с освобождением на exit/reload.
  Normal/specular/emission и MTL-параметры ещё не применяются.
- Standalone Java-проверка `OriginalMenuSceneCheck` проверяет исходные центры
  и границы hotspots/их пересечения, clamp камеры, разгон/ворота, 4 колеса,
  32 рельса, 7 интро-тоннелей, 5 вариантов тоннеля, положение створок,
  отсутствие изменения state при draw и размотку матриц при сбоях.
  Локально CPU-код скомпилирован ECJ в Java 8 bytecode и проверен Java runtime;
  CI дополнительно компилирует его настоящим JDK 8 javac без Forge/OpenGL.
  Это не запуск Minecraft и не проверка визуального совпадения.

## Выполненный пользователем шаг: сбор материалов и текстур сцены

Сформирован автономный `downloads/finishmenu.py` по **реальным ссылкам mtllib**
из проверенных 35 моделей. Требуется Python 3, без pip/Java/других программ.

1. Положить скрипт в исходную папку `content`, где лежат
   `Metro2033Models.jar` и `Metro2033Textures*.jar`.
2. Открыть `cmd` из адресной строки этой папки и выполнить:

```bat
py -3 finishmenu.py "."
```

3. Из новой папки `metro_menu_finish_parts` загрузить все
   `metro_menu_finish_*.zip` и `menu_finish_inventory.json` на тот же Drive.

Сборщик проверяет Models.jar по ожидаемому SHA256, читает 35 исходных `.m2033gl4`,
находит их diffuse-текстуры и доступные normal/specular/emission-каналы.
По умолчанию выбирает максимальное доступное разрешение не выше 512, либо
минимальное выше, если меньших нет. `--size 1024` и другие поддерживаемые
значения позволяют выбрать другой уровень; окончательное разрешение/шейдерное
совпадение с донором ещё не проверены. Сохраняются исходные байты, не перекодировка.
ZIP независимы, каждый не больше 90 MiB. Все пропуски/ошибки записываются в JSON.

Исходные архивы не изменяются. Клиент, Java и сетевые команды не запускаются,
данные аккаунтов не читаются. Никаких дверных add-on-моделей из декора или оружия
в этот сборщик не добавлено. Существующая выходная папка не перезаписывается.
Сборщик материалов проверен на синтетических архивах; на реальных больших
архивах пользователя он здесь не запускался. ZIP — исходники, не игровой мод.
